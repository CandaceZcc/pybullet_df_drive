## 1. 本阶段已完成

- 新增静态、移动和混合障碍物生成。单批数量 `1..50`，场景总数不超过 100；混合模式默认 30% 移动障碍物。
- 障碍物使用请求局部随机数生成器；相同场地、前置障碍物状态、参数和种子会复现相同逻辑布局。
- 新增质量为零的 PyBullet 障碍物刚体。移动障碍物沿直线路径往返，逐帧先重采样地形高度和法向，再在 `stepSimulation()` 前更新位姿和切向速度。
- 地形射线采样限定 `SceneInfo.body_ids`，通过地形专用碰撞组过滤车辆、障碍物自身和其他非地形 body。
- 障碍物添加、删除、清空、快照和恢复由 `ObstacleManager` 管理。大批添加和清空按 2 ms 软预算跨帧让出控制；整批失败不会发布半批逻辑状态。
- Dashboard 新增“障碍物”页，可添加静态/移动/混合障碍物，表格单选逻辑 ID 删除，也可一键清空。
- 场景协调器统一串行处理车型切换、车辆复位、场地切换和障碍物结构操作；场地重建保留障碍物逻辑 ID、XY、路径进度和方向，并重新贴合目标地表。
- 结构操作期间 Dashboard 显示忙碌状态，完成或失败后显示统一状态文本，不弹阻塞物理循环的模态确认框。
- 手动 GUI 会话新增障碍物 JSONL 事件日志，记录添加、删除、清空、场地重建和回滚事件。
- 新增阶段二 DIRECT 自动验收脚本、阶段二 GUI 示例配置和 README 使用说明。
- 完成两轮只读独立复审。首轮发现的性能、路径阈值、碰撞门禁、实际坡面验证和测试文件头注释问题已修复；第二轮复审未发现问题。

## 4. 关键 PyBullet 机制说明

- 障碍物刚体：阶段二障碍物使用质量为零的静态/运动学刚体。静态障碍物参与碰撞并阻挡车辆；移动障碍物由程序逐帧更新位姿，不被车辆撞偏。
- 碰撞 shape 生命周期：创建障碍物时先创建 collision shape，再创建 body；若 body 或 visual 创建失败，会释放已创建的 collision shape，避免批量生成时泄漏。
- 四元数保护：障碍物创建和更新会拒绝非有限或零范数四元数，避免 PyBullet 接受后生成 NaN 位姿。
- 地形过滤：地形 body 使用额外碰撞组位，`probe_terrain()` 的射线只命中地形组，因此车辆或障碍物盖在采样点上方时也不会被误认为地面。
- 跨帧事务：`ObstacleManager.advance_pending_operation()` 每帧推进一段规划、暂存或清理工作。2 ms 是软预算，用测试注入时钟验证会让出控制；100 ms 是阶段二集成验收的硬阻塞上限。
- 场地重建：切换场地时先快照逻辑状态，再清理旧世界，加载目标地形和车辆，并恢复障碍物。目标恢复失败时重建旧世界并恢复快照；回滚失败才抛致命异常。
- 事件日志：障碍物结构事件与高频 CSV 遥测分开写 JSONL。每行记录仿真时间、事件类型、逻辑 ID、请求参数、种子、车型、场地、成功状态和错误原因。

## 6. GUI 操作步骤

进入项目环境后启动阶段二示例：

```bash
conda activate slope-sim
python main.py --config configs/stage2_obstacles_gui.yaml --gui --manual
```

基础操作：

- 打开 Dashboard 顶部“障碍物”页。
- 选择模式 `static`、`moving` 或 `mixed`，填写数量和种子，点击添加。
- 混合模式添加 10 个时，默认应得到 7 个静态和 3 个移动。
- 表格中单选一个逻辑 ID 后点击删除；其他障碍物应保留。
- 点击清空后，所有障碍物应移除。
- 清空后保持同一场地、参数和种子再次添加，形状、尺寸、位置和运动初态应复现。
- 移动障碍物应连续贴地运动，在端点反向；与车辆碰撞后仍沿原路径运动。

场景事务操作：

- 点击“复位车辆”，车辆应回到当前场地出生点，障碍物不变。
- 选择其他车型并点击“应用车型”，当前场地和障碍物不变，旧车体消失。
- 选择 `flat`、`slope` 或 `golf_heightfield` 并点击“应用场地”，障碍物逻辑 ID、XY、路径进度和方向保持，Z 和姿态重新贴合目标地表。
- 持续驾驶期间追加、删除、清空、切换场地和切换 Dashboard 页面，应无明显卡顿、断控或焦点丢失。

退出方式：

- `q`、`Esc` 或 Dashboard 的退出按钮结束手动会话。
- 程序退出时会打印 CSV 路径；如果发生障碍物结构事件，还会打印 `obstacle_event_log` 路径。

## 8. 已知问题和残余风险

- 当前开发环境为 SSH/TTY，真实 PyBullet GUI 未由开发方打开；该自动化覆盖缺口已由用户桌面环境人工验收补充，用户未发现异常。
- DIRECT 验收没有真实 Qt 事件泵，因此阶段二脚本只报告 `max_qt_event_ms=not_measured`；用户 GUI 人工测试已通过，但自动化仍不伪造 Qt 事件间隔数据。
- 批量添加的 2 ms 是软预算，脚本会记录最大结构时间片；当前本机 DIRECT 最大时间片为 `16.33 ms`，低于 100 ms 硬阻塞上限。
- 质量为零的移动障碍物是受控场景对象，不会被车辆撞偏；这符合阶段二场景行为，不代表车辆具备自动避障能力。
- 高尔夫场地仍是硬质 heightfield，不模拟草地、湿地、软土或轮胎下陷。
- 阶段三/四功能尚未实现，README 已明确写为“计划”。
