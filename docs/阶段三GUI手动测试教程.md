# 阶段三 GUI 手动测试教程

本文面向第一次使用 PyBullet 和阶段三 Dashboard 的测试人员，目标是在已经打开的 GUI 手动会话中，完整检查驾驶、车型、场地、障碍物、15 个默认页面以及退出产物。

当前推荐人工检查组合为：

- 接口模式：`local`
- 车型：`active_steering_4wd`
- 窗口：PyBullet 主窗口和标题为“3D仿真Dashboard”的 Dashboard

如果这两个窗口已经打开，请直接从“2. 认识两个窗口”开始，不要同时启动第二套 GUI。

## 1. 测试范围与启动方式

### 1.1 local 模式能验证什么

`--interface-mode local` 使用进程内传输，适合人工检查：

- Dashboard 线速度/角速度设置和键盘驾驶是否能控制车辆；
- 车辆刚体、车轮、转向关节和碰撞反馈是否合理；
- 车型、场地和障碍物能否在运行中切换；
- LiDAR、RTK、IMU、轮组反馈和图表是否随车辆运动；
- Dashboard 页面、滚动区、按钮和文字是否完整可见；
- 日志、图像和场景文件是否正常落盘。

local 模式不能替代真实 eCAL P0 门禁。此模式下“eCAL 未连接”是预期状态，不应记录为 GUI 故障。真实 eCAL 复验必须单独获得授权，并在主机无其他重负载时进行。

### 1.2 需要重新启动时

先确认旧的 PyBullet 和 Dashboard 已正常退出，再在项目根目录执行：

```bash
conda activate slope-sim
cd /home/cancade/pybullet_df_drive
python main.py --gui --manual --interface-mode local \
  --drive-model physics \
  --robot-model active_steering_4wd \
  --terrain-model flat
```

不要添加 `--duration-sec`，这样手动会话会一直运行，直到按 `q`、`Esc` 或点击 Dashboard 的“退出”。默认输出目录为：

- 日志：`results/logs`
- 图像：`results/figures`

需要隔离本次产物时，可以在启动命令中增加：

```bash
--log-dir results/manual_acceptance/logs \
--figure-dir results/manual_acceptance/figures \
--scene-out results/manual_acceptance/final_scene.yaml
```

## 2. 认识两个窗口

正常启动后应同时看到：

1. 左侧 PyBullet 主窗口：显示场地、车辆、障碍物和物理运动。
2. 右侧“3D仿真Dashboard”：显示企业接口状态、图表和场景控制。

GUI 手动模式名义上按主屏可用宽度的 `67:33` 分配两个窗口，Dashboard 宽度按 `33/100` 计算，PyBullet 主窗口使用剩余宽度。人工确认：

- [ ] 两个窗口共享一条边，没有重叠或明显空缝；
- [ ] 两个窗口均未越过桌面可用区域；
- [ ] Dashboard 标题、顶层页签和下方控制区均可见；
- [ ] 顶部页签区和下方控制区大致各占一半高度；切换有数据/无数据页面时分区高度不跳动；
- [ ] Dashboard 下方控制区可以纵向滚动，最底部“清空障碍”和“结构状态”可以到达；
- [ ] 页签栏右侧的左右滚动按钮可用，点击右移后还能通过若干次左移回到开头。

页签较多时，一部分标题被隐藏属于正常现象。可以使用页签栏左右按钮，也可以用：

- `Ctrl+Tab`：切换到下一个页签；
- `Ctrl+Shift+Tab`：切换到上一个页签。

自动化的正式全图表门禁要求 Dashboard client 逻辑高度至少 600px；304/320px 高度只用于检查紧凑布局仍可滚动、文字和控件不重叠。如果人工窗口明显低于 600px，应记录为 compact 观察，不能把它当作完整 15 页绘图门禁结论。

## 3. 基础驾驶

### 3.1 键盘控制

PyBullet 或 Dashboard 窗口获得焦点时，方向键都可以驾驶：

| 按键 | 动作 |
| --- | --- |
| `↑` | 前进 |
| `↓` | 后退 |
| `←` | 左转 |
| `→` | 右转 |
| `q` / `Esc` | 正常退出整个程序 |

当前车型是 `active_steering_4wd`。它是主动转向四驱车，必须同时给出前进或后退命令和左转或右转命令才会沿曲线转弯。只按 `←` 或 `→` 不会像差速车那样原地自转。

建议按以下顺序检查：

1. 在 Dashboard “仿真控制”中把“线速度”设为 `0.80 m/s`、“角速度”设为 `0.60 rad/s`。
2. 按住 `↑` 约 2 秒，确认四个驱动轮转动且车体前进。
3. 同时按住 `↑` 和 `←` 约 2 秒，确认两个前轮产生转角，车辆轨迹向左弯曲。
4. 同时按住 `↑` 和 `→`，确认转角和弯曲方向相反。
5. 按住 `↓`，确认车辆后退。
6. 把线速度改为 `0.30 m/s` 后再次前进，确认运动明显变慢；把角速度改小后再次转弯，确认转向命令幅度变小。
7. 松开全部方向键，确认命令回到零；受加速度限制和物理惯性影响，车辆可以有短暂减速过程。

空格键在两个窗口中的语义不同：

- PyBullet 主窗口有焦点时，空格发送零速度目标，用于停车；
- Dashboard 有焦点时，空格按住期间临时暂停物理步进；松开即恢复，不改变“暂停/继续”按钮的持续状态。

因此需要明确停车时，优先松开方向键并在 PyBullet 主窗口按空格；需要持续暂停时，使用 Dashboard 的“暂停”按钮。

### 3.2 速度设置与输入边界

“仿真控制”区域直接提供两个数值框：

- “线速度”：`0.00..2.00 m/s`，决定 local 模式下前进/后退键的目标速度；
- “角速度”：`0.00..4.00 rad/s`，决定 local 模式下左/右键的目标角速度。

修改后无需点击“应用”，下一次键盘采样立即使用新值。Dashboard 已删除五个方向按钮，驾驶只使用键盘；真实 eCAL 模式由 `/sim/wheel/command` 独占控制，不读取这两个 GUI 速度值。

人工确认：

- [ ] 两个速度数值框完整可见、可修改，单位没有被裁切；
- [ ] 松开键盘后不会一直保留旧驾驶命令；
- [ ] 驾驶时“轨迹”“速度/命令”“驱动命令”和“驱动反馈”页面都有变化；
- [ ] 转弯时“转向命令”“转向反馈”和“RTK航向”页面都有变化。

## 4. 暂停、继续与复位

### 4.1 持续暂停

1. 让车辆缓慢前进。
2. 点击“暂停”。
3. 确认运行状态从“运行中”变为“已暂停”，按钮文字变为“继续”。
4. 观察车辆位置和仿真曲线不再推进。
5. 查看“接口状态”，确认接口状态仍会刷新。
6. 点击“继续”，确认物理步进从当前位置恢复，不会追赶暂停期间的墙钟时间。

若在暂停期间点击了“应用车型”“应用场地”或障碍物操作，结构请求可能显示“等待应用”。点击“继续”后让物理主循环处理该请求。

### 4.2 复位车辆

1. 驾驶车辆离开出生点。
2. 松开所有方向键。
3. 点击“复位车辆”。
4. 等待“结构状态”完成更新。

预期结果：

- [ ] 当前驾驶命令被清零；
- [ ] 车辆回到当前场地的安全出生点；
- [ ] 车型和场地选择不变；
- [ ] 旧车型/旧世界的实时曲线被清空，随后由新样本重新绘制；
- [ ] 程序没有新开第二个车辆或第二个 Dashboard。

## 5. 四种车型

每次切换前先松开驾驶按键，在“机器人”区域选择车型，然后点击“应用车型”。只改变下拉框不会立即切换。

| 车型 | 结构重点 | 图表重点 |
| --- | --- | --- |
| `df_front` | 前置两轮差速驱动，后部支撑 | 驱动命令/反馈各两路；转向页显示“当前车型无转向数据” |
| `df_mid` | 中置两轮差速驱动，前后支撑 | 驱动命令/反馈各两路；可用左右命令原地转向 |
| `df_back` | 后置两轮差速驱动，前部支撑 | 驱动命令/反馈各两路；转向页不应制造虚假零曲线 |
| `active_steering_4wd` | 四轮驱动、两个前轮主动转向 | 驱动命令/反馈各四路，转向命令/反馈各两路 |

对每个车型执行：

1. 选择车型并点击“应用车型”。
2. 等待“结构状态”从“应用中”恢复为完成状态。
3. 确认 PyBullet 中旧车消失，新车只出现一台。
4. 前进、后退和转弯各操作一次。
5. 打开驱动与转向页面，确认曲线数量符合上表。
6. 点击“复位车辆”，确认仍复位当前车型。

车型切换会从当前场地的安全出生点加载目标车型并使旧命令失效。若切换失败，Dashboard 应显示错误，原来的有效车型和场地应继续存在。

## 6. 三种场地

场地参数只在对应场地被选中时启用：

- `flat`：平面，不使用坡度、随机种子和起伏参数；
- `slope`：斜面，启用“坡度”，范围为 `-30` 到 `30 deg`；
- `golf_heightfield`：高尔夫起伏地形，启用“随机种子”和 `low/medium/high` 起伏选项。

只改变下拉框或数值不会立即重建场地，必须点击“应用场地”。建议按以下顺序测试：

1. 选择 `flat`，点击“应用场地”，前进一段距离。
2. 选择 `slope`，设置 `8 deg`，点击“应用场地”，观察车体爬坡、RTK 高度和 IMU 姿态变化。
3. 选择 `golf_heightfield`，设置随机种子 `41`、起伏 `medium`，点击“应用场地”，观察车体姿态随起伏变化。
4. 再次应用完全相同的高尔夫种子和起伏，确认地形布局可复现。
5. 选择 `active_steering_4wd`，先添加 20 个混合障碍，再从 `flat` 应用 `golf_heightfield`；确认选择不会回弹到 flat，20 个障碍的逻辑 ID、XY 和移动路径仍保留。

应用场地会调用 PyBullet 的 `resetSimulation()`，所以车辆也会重建；这是正常现象。实时曲线会清空，CSV 仍属于同一个手动会话，并通过每行字段记录切换后的车型和场地。

场地切换后检查：

- [ ] 只有一台当前车型；
- [ ] 车辆位于新场地的安全出生点，没有埋入或悬空；
- [ ] `RTK位置` 的 `z` 与场地高度相符；
- [ ] `IMU姿态` 的 roll/pitch 会随斜坡或起伏变化；
- [ ] 已有障碍物的逻辑 ID、XY、移动进度和方向被保留，并重新贴合目标地表；
- [ ] 发生错误时回滚到上一个有效场景，Dashboard 显示错误而不是留下半重建世界。

## 7. 添加、删除和清空 20 个障碍物

先切换到“障碍物”页，以便同时观察表格。再滚动 Dashboard 下方控制区到“障碍物”组，设置：

- 模式：`混合`
- 形状：`圆柱`，也可以另行测试方块和球体
- 数量：`20`
- 随机种子：`41`
- 速度：`0.35`
- 移动占比：`30%`

点击“添加障碍”后等待“结构状态”完成。预期：

- [ ] PyBullet 中出现 20 个障碍物；
- [ ] 表格出现 20 行，列名为“逻辑ID、模式、形状、位置”；
- [ ] 20 个混合障碍中有 14 个 `static`、6 个 `moving`；
- [ ] `moving` 障碍沿路径往返，表格位置会刷新；
- [ ] 障碍物可与车辆发生碰撞，但移动障碍不会被车辆撞离预定路径；
- [ ] LiDAR 点云会随车辆与障碍物相对位置发生变化。

继续验证删除和清空：

1. 在表格中单击任意一行，确认整行被选中。
2. 点击“删除选中”，确认该逻辑 ID 消失，表格剩 19 行，PyBullet 中对应障碍物消失。
3. 点击“清空障碍”，确认表格变为 0 行，场景中不再有这些障碍物。
4. 用相同参数重新添加 20 个，记录位置；再次清空并用相同参数添加，确认几何布局可复现。逻辑 ID 可以递增，不要求与上次相同。

静态模式下“速度”和“移动占比”不可编辑；移动模式下只启用“速度”；混合模式下两者都启用。这是防止无效参数误操作的正常状态。

默认企业 Dashboard 必须正好有以下 15 个一级页签。先驾驶和转弯数秒、添加障碍物，再逐页检查，这样图表中有足够数据。

| 序号 | 页面 | 人工检查重点 |
| ---: | --- | --- |
| 1 | 接口状态 | “传输模式”为“本地测试模式”，“eCAL 连接”为“eCAL 未连接”；轮子命令、轮子状态、前雷达、后雷达、RTK、IMU 六组状态持续刷新，时间戳和实际频率不是长期冻结值 |

| 14 | 传感频率 | 前雷达、后雷达、RTK、IMU 四条曲线持续刷新，正常运行时应稳定在目标频率附近 |
| 15 | 接口异常 | 正常 local 会话中 errors/s 和 drops/s 应保持为零；出现非零值时记录发生时刻和此前操作 |

逐页还要检查以下通用项目：

- [ ] 当前页签文字完整，图表标题、x/y 标签、刻度、offset 和图例都在画布内；
- [ ] 任何文字、图例、刻度和按钮之间都没有明显重叠；
- [ ] 图表画布非空，切换页面不会把 Dashboard 尺寸挤动；
- [ ] 顶部页签区和下方控制区高度肉眼接近 `1:1`，记录增长前后都不改变；
- [ ] 曲线增长、清空或 LiDAR 点数变化时，绘图区位置和大小保持稳定，并至少占画布宽度约 60%、高度约 50%；
- [ ] 折线页同时存在“清空曲线”和“保存当前图”；
- [ ] LiDAR 页只有“保存当前图”，没有“清空曲线”；
- [ ] 每个可见按钮都能点击，文字没有超出按钮边界；
- [ ] 页签横向滚动和下方控制区纵向滚动后，仍能返回原位置。

建议在每个图表页先点击“保存当前图”，再点击“清空曲线”。“清空曲线”会清空折线历史，继续运行后当前数据会重新积累；LiDAR 点云不使用该清空按钮。保存文件名形如：

```text
results/figures/dashboard_plot_轨迹_YYYYMMDD_HHMMSS.png
```

如果差速车型的“转向命令”和“转向反馈”显示“当前车型无转向数据”，这是正确结果；不应为满足图表外观而绘制虚假的零值转向曲线。

### 8.1 怎样把 LiDAR 图和实际障碍联系起来

LiDAR 页使用车辆自身的 `base_link` 坐标系，不是俯视世界地图：箭头所在 `(0,0)` 是车体参考点，箭头方向和 `+X` 都表示车头前方，`+Y` 表示车体左侧。前后雷达各自在不同时间扫描，所以转弯或移动障碍场景中，两组点允许有轻微时间差。

建议先只添加一个静态障碍，再按以下顺序观察：

1. 让车辆正对障碍，确认障碍命中集中在图的 `+X` 一侧；倒车越过或掉头后，点应移动到相反方向。
2. 转动车头，确认同一障碍相对车辆坐标发生旋转，而车辆箭头始终不动。
3. 再添加一个移动障碍，结合图例确认静态与移动障碍颜色不同；点表示被射线击中的表面，不会画成完整实体轮廓。
4. 驾驶接近障碍时，点到原点的距离应缩短；30 m 虚线环提供固定距离参照，坐标轴不能随点云自动缩放。

## 9. 开发者诊断边界

默认 15 页中不应出现以下内部诊断：

- 接触法向力和摩擦力；
- 有效接触点数；
- 打滑率和打滑速度；
- 内部地面法向和相机调试参数。

这些指标默认隐藏是阶段三产品要求，不应把它们缺席记录为失败。需要调试时，先正常退出当前 GUI，再用原命令加 `--developer-diagnostics` 重新启动：

```bash
python main.py --gui --manual --interface-mode local \
  --drive-model physics \
  --robot-model active_steering_4wd \
  --terrain-model flat \
  --developer-diagnostics
```

此时应在 15 个默认页之后增加第 16 页“开发者诊断”。该页只包含内部遥测和相机控制；线速度和角速度仍位于默认“仿真控制”区：

- “启用跟随”：即时开关，不需要点击应用；
- “车后”：相机在车后并随车辆 yaw 旋转；
- “侧面”：从侧面跟随并随车辆 yaw 旋转；
- “固定”：跟随车辆位置，但保持配置的世界 yaw；
- 关闭“启用跟随”：可以在 PyBullet 窗口中自由调整相机。

不要为了查看开发者诊断而并发启动第二套 PyBullet/Qt 会话。

## 10. 正常退出与输出文件

完成测试后，使用以下任一方式正常退出：

- Dashboard 的“退出”按钮；
- Dashboard 或 PyBullet 窗口中的 `q`；
- Dashboard 或 PyBullet 窗口中的 `Esc`。

不要直接杀死进程。正常退出会依次关闭接口、Dashboard、CSV/障碍物日志，最后断开 PyBullet，并在终端打印实际路径。检查终端中的：

| 输出前缀 | 内容 | 默认位置 |
| --- | --- | --- |
| `log:` | 本次手动会话 CSV | `results/logs` |
| `figure:` | 退出时生成的轨迹图 | `results/figures` |
| `feedback_figure:` | 打滑、接触/摩擦反馈图 | `results/figures` |
| `diagnostic_summary:` | 根据 CSV 计算的诊断汇总 | CSV 同目录 |
| `obstacle_event_log:` | 添加、删除、清空和结构操作事件 | `results/logs` |
| `interface_binary_log:` | 可重放的接口二进制消息日志 | `results/logs` |
| `interface_event_log:` | UTF-8 接口事件日志 | `results/logs` |

默认 Dashboard 隐藏打滑和接触指标，但退出时仍可以生成对应反馈图和诊断汇总；这是离线证据，不代表这些指标重新进入默认企业页面。

最终确认：

- [ ] 终端正常返回，没有未处理异常；
- [ ] CSV 和障碍物事件日志存在且非空；
- [ ] 接口二进制日志和事件日志均存在；

- [ ] 指定 `--scene-out` 时，场景文件存在；
- [ ] 退出后两个窗口都消失，没有残留第二套 GUI。

## 11. 常见现象与处理

| 现象 | 处理 |
| --- | --- |
| 方向键没有反应 | 先点击 PyBullet 或 Dashboard 窗口取得焦点；确认没有处于“已暂停”状态 |
| 主动转向车只按左右不动 | 同时按前进/后退和左/右；该车型不支持只靠转向轮原地自转 |
| local 模式显示“eCAL 未连接” | 正常；确认“传输模式”为“本地测试模式”，不要把它当作真实 eCAL 验收 |
| 页面标题看不全 | 使用页签栏左右按钮，或 `Ctrl+Tab` / `Ctrl+Shift+Tab` |
| 底部控件看不全 | 在 Dashboard 下方控制区使用鼠标滚轮或滚动条，不要缩放窗口绕过检查 |
| 图表暂时空白 | 驾驶或转弯数秒后重新打开该页；图表按较低显示频率刷新，不会每个物理帧重绘 |
| 结构状态一直“等待应用” | 若当前已暂停，点击“继续”；松开驾驶输入后等待结构事务完成 |
| 切换失败 | 记录“结构状态”错误文字；确认旧的有效车型和场地仍可驾驶，不要连续快速点击应用 |
| 车辆停止响应且越界 | 松开全部输入，点击“复位车辆”；记录越界前的车型、场地和操作 |
| 保存图后找不到文件 | 查看启动时的 `--figure-dir`；未指定时到 `results/figures` 查找 `dashboard_plot_*.png` |

## 12. 通过标准

一次完整的 local GUI 人工验收至少满足：

1. 两个窗口按 `67:33` 布局，Dashboard 内上下区按 `50:50` 分配，无重叠、越界和不可达控件。
2. 默认线速度和角速度设置能改变 local 键盘驾驶，主动转向四驱的轮速、转角和车体运动一致。
3. 暂停、继续和复位行为正确，不恢复旧命令，也不追赶暂停墙钟。
4. 四种车型和三种场地均能应用并驾驶，切换后只有一个有效世界。
5. 能添加 20 个障碍物、删除选中项并清空，表格和物理场景一致。
6. 15 个默认页面全部可达，图表、文字、刻度、图例和按钮无裁切或重叠。
7. LiDAR、RTK、IMU、轮速和转向反馈随真实物理状态变化，正常 local 会话无接口错误或丢帧。
8. 程序正常退出并打印完整日志、图像和可选场景路径。

以下内容不属于本次 local GUI 通过条件：

- eCAL 显示为已连接；
- 真实跨进程 eCAL 频率和 transport drop P0；
- 默认页中出现打滑、接触力或接触点数；
- 阶段四的自动导航、自动刹停、路径规划和动态避障。
