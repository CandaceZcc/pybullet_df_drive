# 阶段四 A：v2 协议与命令权说明

本文说明阶段四 A 已建立的 Python/C++ 线协议、仿真会话和单命令源规则。它不改变阶段三生产 runtime；单 LiDAR、三点 RTK、Recorder、ROS 2 和发行包分别属于后续阶段。

## 基本概念

- eCAL 是同机多进程实时消息总线。本项目只把它当作传输管道，不让它决定 PyBullet 的物理真值。
- Protobuf v2 是 Python/C++ 共用的线格式。每条顶层消息携带 descriptor SHA-256，以证明双方使用同一份 schema。
- `simulation_session_id` 在每次 Simulator 进程启动时生成，防止重启前后的消息被拼接成同一次运行。
- `world_generation` 只在成功提交换车或换场景时递增；四个输出话题的 sequence 从 0 重新开始。
- `command_generation` 在命令源丢失、冲突、撤权或 world rebuild prepare 时递增。旧控制 token 永不恢复。

v2 使用五个固定话题：`/sim/wheel/command`、`/sim/wheel/state`、`/sim/lidar/front/points`、`/sim/rtk/state` 与 `/sim/imu/attitude`。它们的远端 type、`proto` encoding 和 descriptor 必须先被验证，raw payload 才能交给 worker 解析。

## 命令权状态

| 状态 | 精确 peer 数 | owner | 含义 |
|---|---:|---|---|
| `WAITING` | 0 | 无 | 没有命令发布者，车辆保持安全停车。 |
| `CLAIMABLE` | 1 | 无 | 有且仅有一个发布者，可以用 sequence 0 认领。 |
| `ACTIVE` | 1 | 已绑定 | 同一 source/session 以递增 sequence 持续控制。 |
| `CONFLICT` | 大于 1 | 无 | 发布者冲突，撤权并保持安全停车。 |

状态机在每轮接收前先调用 `poll_peer_state()`，再读取 snapshot 或 peer count。这样 snapshot 才代表本轮最新 discovery/metadata；反过来读取会得到旧连接状态。`ProtocolSession` 只保存会话、world generation 和输出 sequence，`CommandAuthority` 单独保存 owner、peer count 和 command generation，避免两种 generation 相互推进。

## 断线与重连流程

1. 命令 peer 断开时，authority 失去 owner，递增 `command_generation` 并令 mailbox 安全停车。
2. peer 恢复后，transport 先完成远端 metadata 验证；未验证或冲突时不投递 payload。
3. runtime 读取新的 `WheelState`，确认 `CLAIMABLE`、新的 command generation 与当前 world generation。
4. 控制端以 sequence 0 发送新的 `WheelCommand` 并认领 owner；之后只接受相同 source/session 的严格递增 sequence。

可用下列命令检查五种冻结的跨语言 raw bytes。它们不启动 eCAL participant：

```bash
export STAGE4_PHASE0_BUILD_DIR="$PWD/build/stage4-phase0-ecal611-release-mapped-20260809T220738+0800"
conda run -n slope-sim python scripts/generate_stage4_v2_goldens.py
conda run -n slope-sim python -m pytest -q tests/stage4/test_cpp_v2_interop.py
```

第一条只重编码并逐 byte 校验仓库内五个 fixture；发现 schema、Python serializer 或 manifest 漂移会非零退出。第二条要求 C++ `v2_golden` 同时完成 Python 到 C++ 解码和 C++ 到 Python 的逐 byte 比较。

## 已证明与未接线范围

阶段四 A 已证明 v2 descriptor、会话/命令权状态机、Python/C++ deterministic golden 与真实 eCAL raw Phase-0。真实 Phase-0 的同 topic v1/v2 冲突被硬拒绝，`accepted_count=0`。

阶段 A 不生成半正确的 LiDAR/RTK runtime 数据，也没有交付 C++ SDK、MCAP Recorder、ROS 2 bridge、RViz2/Livox viewer 或发行包；这些项目必须在后续阶段独立验收。
