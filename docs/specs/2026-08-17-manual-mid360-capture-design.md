# 手动 MID-360 采集与 Livox Viewer 导入设计

## 目标

让用户只用 `runSim` 完成一次手动采集：在 Dashboard 选择车辆和地形，启用采集，在主 PyBullet GUI 用方向键驾驶，结束采集，生成可由 Livox Viewer 2 打开的 `.lvx2`，再由 Dashboard 自动导入该文件。

该功能追求与 MID-360 离线映射相同的扫描模式和文件兼容性，不把旧的圆形双雷达俯视图当作映射点云。

## 非目标

- 不在驾驶期间启动 Livox Viewer 2 或实时向其推送点云。
- 不保留旧 Dashboard 的圆形 LiDAR 点云页、“打开实时点云”按钮和相关导出入口。
- 不让 `runSim --lidar` 启动独立的自动 Golf 映射流程；日常入口为无参数 `runSim`。
- 不改变显式 eCAL 外部控制入口的语义。

## 用户流程

1. 用户运行 `runSim`，出现主 PyBullet GUI 与 Dashboard。
2. 用户在 Dashboard 选择地形和车辆，并等待结构切换完成。
3. 用户在“采集”区域选择最长采集时长：`1 分钟`、`1.5 分钟`、`3 分钟` 或 `不限`；默认 `1 分钟`。
4. 用户点击“启用采集”。Dashboard 冻结车辆、地形和场景结构选择，进入“采集中”。
5. 用户把焦点放在主 PyBullet GUI，用方向键驾驶；Dashboard 只记录轨迹、姿态和时间，不执行高密度射线扫描。
6. 用户点击“结束采集”，或达到所选上限。Dashboard 进入“正在生成 LVX2”。
7. 后台重建完成并校验成功后，Dashboard 显示本次输出的绝对路径，并启用“导入 Livox Viewer”。
8. 用户点击该按钮；程序启动 Livox Viewer 2，并通过已验证的 X11 文件选择流程自动选中、打开本次 `.lvx2`。

`不限` 仍显示已经采集的时长、预计重建规模和磁盘增长提示，但不会自动停止。

## 架构

### 驾驶期采集

`runSim` 保持当前本地手动控制路径：主 GUI 的方向键直接驱动车辆，Dashboard 仅处理 Qt 事件和状态。

新增一个受 Dashboard 状态机驱动的手动采集记录器。启用采集时，它冻结当前逻辑场景文档、world generation 和车辆模型；随后在每一个物理步记录主动机器人位姿、仿真时间及必要的运动状态。场景结构在采集期内锁定，防止回放世界与驾驶世界不一致。暂停和结束采集仍可用。

该记录器不创建旧的双雷达接口、不绘制圆形点云、也不执行 raycast；因此启用采集本身不能把方向键驾驶降到此前 2–3 FPS 的扫描负载。

### 结束后的高保真重建

结束采集后，主 GUI 与 Dashboard 保持可见，但驾驶被安全停止。独立的后台重建进程以冻结的场景文档和轨迹记录建立 DIRECT PyBullet 世界，在每个 10 Hz 扫描时间点按轨迹恢复车体姿态。

它复用既有 MID-360 离线高保真 profile：每 100 ms 20,000 个 firing slot、5 µs slot 间隔，即 200 kHz 发射时序；点仅在射线实际命中时写入。输出为已有 v2 protobuf MCAP 合同的 `session.mcap`，随后调用既有 Stage4 exporter 生成 `export/lidar.lvx2`。因此 `.lvx2` 有正式的 Reader/Exporter 校验边界，而不是把 CSV、PNG、PCD/PLY 或旧 `.interfaces.bin` 伪装成 Viewer 文件。

重建占用 CPU 只发生在结束之后；Dashboard 显示阶段进度、已完成扫描帧数以及失败原因。重建异常、MCAP 验证异常或 LVX2 验证异常均禁止 Viewer 导入。

### 输出与导入

每次采集创建唯一目录：

`results/manual-mid360/<会话编号>/`

目录含冻结场景、轨迹记录、`session.mcap`、`export/lidar.lvx2`、导出回执和失败信息（如果有）。不会覆盖旧会话。

“导入 Livox Viewer”仅在 `.lvx2` 已存在且全文件验证通过后可用。启动逻辑采用现有 Linux Viewer 隔离启动方式；随后自动完成原生文件选择。成功须由 Viewer 日志中的实际 `OpenLvxFile(...lvx2) success` 确认，不能只因进程已启动就报告成功。若 Viewer 缺失、显示环境不支持、启动失败或导入超时，Dashboard 保留文件绝对路径并显示可操作错误。

## Dashboard 状态机

状态为：`未采集` → `采集中` → `正在生成 LVX2` → `已完成` 或 `失败`。

- `未采集`：启用采集可用；结束和导入不可用。
- `采集中`：结束可用；车辆、地形和结构修改禁用；显示已用时与所选上限。
- `正在生成 LVX2`：所有采集按钮禁用；显示重建、MCAP 校验、导出、LVX2 校验的当前阶段。
- `已完成`：显示 `.mcap` 与 `.lvx2` 的绝对路径；导入按钮可用。
- `失败`：显示失败阶段与原因；导入不可用；允许开始一次新采集。

用户手动结束和时长到期共用同一 finalize 路径。退出 `runSim` 时，若正在采集或重建，程序安全终止子进程并把会话标记为未完成，禁止以后导入。

## 性能与容量边界

驾驶期只写少量轨迹数据，验收重点是启用采集前后手动操作的帧率基本一致。高密度 200 kHz 扫描不与驾驶并发。

重建耗时和体积随驾驶时长、地形和命中率线性增长。默认时长取 1 分钟；用户可显式选择更长或不限。选择“不限”时，Dashboard 只发出持续性警告而不擅自终止采集。实现与测试不得制造超过 5 GiB 的采集制品；超过该预估阈值前必须要求用户确认。

Livox Viewer 2 仅在生成完成后启动，避免它与 PyBullet GUI 竞争这台 Iris Xe 共享显存与 CPU；不承诺实时 Viewer 预览。

## 测试与验收

重要生产行为采用 TDD：先为以下契约添加失败测试，再实现最小代码使其通过。

1. Dashboard 采集状态机：按钮可用性、上限选项、结构锁定、超时与手动结束共享 finalize。
2. 手动循环：采集中记录轨迹但不调用高密度扫描；方向键控制路径不变。
3. 离线重建：给定冻结场景与确定轨迹，生成合法 v2 MCAP；解析后的时间、姿态、MID-360 firing offset 和会话身份一致。
4. 导出：既有 exporter 产生完整 LVX2，解析器验证完整 EOF、帧数、包数和点数。
5. Viewer 启动：失败路径不启用导入；成功判据为日志出现实际 `OpenLvxFile` 成功记录。

手工验收：

1. 运行 `runSim`，确认主 GUI 与 Dashboard 同时出现，方向键可驾驶。
2. 选择车辆和地形，启用 1 分钟采集；比较启用前后的可操作帧率。
3. 结束采集，观察生成进度，确认 `results/manual-mid360/<会话编号>/export/lidar.lvx2` 出现且路径在 Dashboard 可见。
4. 点击导入，确认 Livox Viewer 2 自动打开文件，并在日志看到成功打开记录。
5. 分别验证 1.5 分钟、3 分钟与不限模式的提示和停止行为；中途退出确认不会出现可导入的不完整 LVX2。
