# v3 问题处理

## 1. 目的与边界

本文是当前 v2 实时仿真的故障处理执行单，不代表问题已经修复。目标是在同一阶段内完成以下事项，并用可重复证据验收：

1. 修复键盘无法驱动车辆。
2. 定位并修复运行一段时间后卡死、异常退出和子进程清理失败。
3. 完成真实遥控器信号识别、方向映射、安全门禁和车辆控制验收，不延期到后续阶段。
4. 让 RTK、IMU、转向命令和转向反馈图表使用正式 v2 数据源；对不支持主动转向的车型给出明确状态。
5. 正式 v2 模式删除与 `v2 eCAL` 重复的旧“接口状态”页，只保留 `v2 eCAL` 作为实时传输状态页。
6. 修复 `v2 eCAL` 页无法滚动、内容重叠、状态含义错误、实时点云入口误导和 verifier evidence 文案问题。

本阶段不构建新的 `.run` 安装包。只有全部验收通过，才进入发行制品阶段。

## 4. 完成判据

所有判据必须满足，不能以“页面有数据”代替车辆控制验收。

- 键盘：按下前进、后退、左转、右转时，候选目标、C++ 发布帧、authority 接收结果、wheel state 和车辆位姿形成同一条可追踪证据链；松键后安全归零。
- 遥控：完成中位、前、后、左、右、锁定、解锁的真实帧识别；方向与幅值正确；信号丢失 100 ms 内输出归零；恢复后必须重新锁定再解锁。
- 控制源切换：键盘与遥控器切换时先输出零，再转移所有权；不能同时叠加两个来源。
- 稳定性：至少连续运行 30 分钟，无 GUI 假死、无高 CPU 残留循环、无 zombie 子进程；正常退出后所有子进程在有界时间内结束并生成结束摘要。
- 图表：RTK、IMU 使用 v2 实时数据更新；`active_steering_4wd` 显示两路转向命令/反馈；`df_mid` 显示不支持主动转向而不是空图。
- 页面：1366x768 和当前侧栏窄宽度下可滚动、无重叠、所有控制可达；内嵌实时点云可见且外部 ROS/RViz 能力状态明确。
- eCAL：五路话题的 discovery、协议状态、频率、最后更新时间和最近错误原因具有可解释值，不再长期全部显示 `not_checked`。
- 证据：离线 verifier evidence 缺失不会把正常实时运行标为失败；缺失时只显示“未加载离线验收证据”。

### P0-4：真实遥控器识别与控制闭环

遥控器必须在本阶段完成。当前硬编码的通道 5/2/0 只是假设，确认前不能用于车辆运动。

**A. 只读识别工具**

在 `slope_sim/serial_rc.py` 的现有 SBUS parser 上增加最小只读识别入口；可使用单一小脚本 `scripts/identify_rc_channels.py` 调用现有 parser。该入口必须满足：

- 只打开用户指定的 `/dev/serial/by-id/...` 设备并接收原始帧。
- 只显示每个通道的值、变化量、中心值和时间，不创建 `CommandSourceArbiter`，不连接 Command IPC，不向遥控设备或车辆发送任何数据。
- 输出有界，可保存一份本阶段识别证据，不持续录制。
- 识别工具退出或串口断开不会触发运动命令。

**B. 需要用户操作时的交互检查点**

到达真实采样步骤后，由执行者先发消息通知用户，再一次只要求一个安全动作。固定顺序如下；收到并保存当前动作样本后才请求下一项：

1. 所有摇杆与开关保持中位/锁定。
2. 仅前推方向控制。
3. 仅后拉方向控制。
4. 仅左打方向控制。
5. 仅右打方向控制。
6. 仅切换到锁定。
7. 仅从锁定切换到解锁。

识别期间只接收和比较原始帧，绝不向遥控器发送数据。执行者根据样本计算并向用户报告：变化通道、正负方向、中心、有效最小/最大值、死区、解锁沿；用户确认后才写入映射。

**C. 映射与安全门禁**

- 在现有 `RcCommandGate` 的最小配置面内编码已确认的通道、符号、中心/范围和死区；本阶段不新增未经需要的通用配置系统。
- 锁定 -> 解锁必须形成新鲜边沿；启动时已经处于解锁位置不能直接运动。
- 丢帧、串口读取失败、parser 失步、IPC 中断或帧龄超过 100 ms 时立即输出零并撤销解锁状态。
- 恢复信号后必须重新锁定再解锁。
- 键盘与遥控切换时先发零，再切换 owner；未选中的来源不能续租。

### P1-1：v2 图表与车型语义

**根因**

旧图表缓冲由 v1 `InterfaceDashboardSnapshot` 更新，而 `V2DashboardEcalReceiver` 只更新 `V2DashboardWidget`，两条路径未连接。

**最小实现**

- 以 `V2DashboardSnapshotStore` 的不可变 snapshot 作为 RTK、IMU、wheel command/state 图表源，不让 Qt 直接读取接收线程中的可变对象。
- RTK 至少显示位置、速度和航向；IMU 显示姿态与角速度合同中已有字段。
- `active_steering_4wd` 显示两个主动转向通道的命令与反馈。
- `df_mid` 的主动转向数组按车型合同为空，页面显示“车型不支持主动转向”；不得伪造零值曲线。
- 图表只更新可见页并保持已有有界缓冲/降频策略，避免重新引入 GUI 卡顿。

### P1-2：正式 v2 删除重复“接口状态”页

正式 v2 模式下，“接口状态”与 `v2 eCAL` 表达同一实时接口域，因此删除旧“接口状态”tab，只保留 `v2 eCAL`。本项只删除正式 v2 的重复入口；若 local/v1 模式仍依赖旧页，则保留该模式的旧页，不能误删其唯一诊断入口。

### P3-1：eCAL 状态与 verifier evidence 语义

**eCAL 状态**

- raw observer 把真实 discovery、远端 type/encoding/descriptor 校验和最近帧时间投影到 `V2DashboardSnapshotStore.refresh_transport(...)`。
- 有数据但尚无完整 peer 质量信息时显示“已收帧/待质量检查”，不能长期保持默认 `not_checked`。
- 过期、断连、协议拒绝分别显示，错误提示带来源，不把所有异常压成一个红色计数。

**Verifier evidence**

- verifier evidence 移到“离线验收证据”或折叠诊断区。
- 未提供时显示“未加载离线验收证据”，不影响实时 topic 健康状态、内嵌点云和车辆控制。
- 只有用户主动加载证据后，才校验 identity、hash、topic counts 和 clean shutdown。

## 6. 人工验收脚本

按以下顺序执行，每步保存一次截图或结构化日志。任何 P0 失败立即停止后续带运动步骤。

1. 用第 2 节命令启动 `df_mid`，确认 GUI、PyBullet 和 `v2 eCAL` 均出现。
2. 确认正式 v2 没有旧“接口状态”tab，`v2 eCAL` 可滚动到底且无内容覆盖。
3. 静置 10 秒，确认 RTK/IMU 更新、LiDAR 内嵌点云可见，authority 与 observer 状态分开。
4. 依次按 `W/S/A/D` 各 2 秒，核对 target、wheel command、authority、wheel state 和位姿。
5. 松开按键，确认归零；执行一次键盘来源到遥控来源切换，切换中间必须有零命令。
6. 执行 P0-4 的七步只读遥控采样；每次都先由执行者发消息通知用户当前唯一动作。
7. 用户确认映射后，在仿真中验收遥控前、后、左、右、锁定、失联和恢复重解锁。
8. 安全台架验收通过后才进行低速落地遥控测试。
9. 连续运行 30 分钟，期间切换图表、滚动 v2 页和展开/收起点云；确认 GUI 不假死且日志有界。
10. 正常退出，检查结束摘要、子进程退出和无 zombie；再执行一次受控异常退出以验证原始错误和 cleanup 证据都保留。
