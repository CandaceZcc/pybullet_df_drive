# 遥控器串口测试参考

`scripts/test_rc_sticks.py` 是只读诊断工具：它只打开串口、解析 SBUS 帧并打印两个操纵杆的输入，绝不会启动仿真、解锁遥控器或发送小车控制命令。

## 使用前准备

1. 先让小车断电或悬空，遥控器与接收机上电。
2. 只使用稳定设备路径 `/dev/serial/by-id/`，不要使用会变化的 `/dev/ttyUSB0`。
3. 确认 Python 环境已安装 `pyserial`。若提示缺少依赖，请按项目环境说明安装后重试。

查看可用稳定串口：

```bash
ls -l /dev/serial/by-id/
```

## 运行

只有一个稳定串口时可自动选择：

```bash
python3 scripts/test_rc_sticks.py
```

推荐明确指定设备并测试十秒：

```bash
python3 scripts/test_rc_sticks.py --port /dev/serial/by-id/<你的接收机设备名> --duration 10
```

程序输出示例：

```text
CH3 前后: 1722 (+1.000) | CH1 转向: 1002 (+0.000)
采样汇总：frames=986 CH1 min/max=282/1722 CH3 min/max=282/1772
```

## 当前映射

| 操作 | SBUS 通道 | 程序显示 | 说明 |
| --- | --- | --- | --- |
| 左操纵杆前后 | CH3（索引 2） | `CH3 前后` | 实测最小约 282，中心约 1002，机械极端可到 1772 |
| 右操纵杆左右 | CH1（索引 0） | `CH1 转向` | 校准最小/中心/最大为 282/1002/1722，以实机汇总为准 |

归一化按中位 1002 非对称分段计算，超出校准最大值 1722 的实机余量会限幅为 `+1.000`，不会再被 parser 当作坏帧停车。程序允许的原始输入上限为 1772。

## 验收步骤

1. 两杆都居中，两个归一化值应接近 `0.000`。
2. 仅推动左杆前后，只有 `CH3 前后` 应明显变化。
3. 仅推动右杆左右，只有 `CH1 转向` 应明显变化。
4. 若通道与上述映射不符，记录每个杆位对应的输出值；在接入控制功能前再调整映射，勿通过本测试程序直接控制车辆。

无输出时，先确认接收机以 SBUS 115200 波特率输出、串口路径正确且当前用户在 `dialout` 组。出现多个稳定串口时，必须使用 `--port` 明确指定。

若打开时返回 `[Errno 5] Input/output error`，说明还没进入 SBUS 解析：先关闭占用串口的程序并重新插拔接收机，再检查 `fuser -v /dev/ttyUSB*` 和 `journalctl -b | grep -Ei 'ttyUSB|ftdi|usb.*disconnect|ModemManager'`。如 ModemManager 持续探测 FTDI 口，应由系统管理员为该设备添加 `ID_MM_DEVICE_IGNORE=1` udev 规则；不要在仿真运行中盲目重置整个 USB 总线。
