## 1. 本阶段交付范围

- 用版本化 Protobuf 定义轮子命令、实际轮态、前后多线点云、双天线 RTK 和 IMU 消息；六个固定话题由同一配置维护。
- 接入 Eclipse eCAL 6.1.1 正式 Python transport。仿真端订阅 100 Hz 轮子命令，发布 100 Hz 实际轮态和四个 10 Hz 传感器话题。
- 轮子反馈来自 PyBullet 实际关节状态，不回显命令；100 ms 无新命令时安全停车，主动转向车型保持超时瞬间的实际转角。
- eCAL 断线会清除旧命令代际。session attach 和周期读取都先 poll discovery、再读快照；独立 discovery gate/revision 阻止迟到旧观察回退状态，关闭等待在途 count API 后才销毁 native 资源。
- 自动实验、GUI 手动入口和独立 eCAL 仿真进程共享 50 ms runtime 观测节拍；discovery/组合快照为 20 Hz，命令超时、安全控制和物理步仍逐帧执行。
- 前后 LiDAR 使用独立安装位和完整多线射线，后雷达相对前雷达错相 50 ms；生产 runtime 在发布时刻用一次 `rayTestBatch` 生成原子点云。生产后端使用紧凑 indexed-hit 与预验证逆变换，headless 路径不构造 Dashboard 俯视副本，地形、车辆和障碍物使用碰撞 group/mask 隔离自击与误击。
- RTK 输出主天线世界坐标和主天线指向副天线的 yaw；IMU 输出车体 roll/pitch。两者与 PyBullet 真值使用同一仿真时钟。
- 支持包含车型、场地、障碍物、LiDAR 参数和五个传感器安装位的版本化场景导入、原子导出、重建与失败回滚。
- 企业 Dashboard 默认提供 15 个页面，其中 13 个为图表页，并展示逐话题连接/频率/时间戳/错误状态、20 秒曲线和前后点云俯视图；旧业务图默认只保留 `轨迹`、`速度/命令`，接触力、接触点数和打滑指标仅在显式开发者诊断中显示。
- 主 GUI 与 Dashboard 在主屏可用区域按名义 `67:33` 初始平铺：Dashboard 宽度精确按 `33/100` 计算，Main 使用余宽。验证器使用 XRes PID 所有权认领窗口，不依赖容易冲突的窗口标题。
- 高频接口日志由有界异步队列写入长度前缀 Protobuf 和 JSONL；快照同时报告 queued 与 in-flight 的未完成落盘数。

阶段四自动刹停、全局路径规划、局部动态避障和导航状态机未开始。

## 6. 用户 GUI/eCAL 人工验收步骤

人工验收不设置倒计时，用户可按需要停留和重复观察。

1. 安装并启动 eCAL Monitor，进入 `slope-sim` 环境，在桌面运行：

   ```bash
   python main.py --gui --manual --interface-mode ecal \
     --robot-model df_back --terrain-model flat --drive-model physics
   ```

2. 在 Monitor 中确认六个固定话题、Protobuf 类型、发布/订阅方向和频率；Dashboard 的逐话题状态应与 Monitor 一致。
3. 向 `/sim/wheel/command` 发布 `df_back` 的两个驱动轮速度，确认车辆方向和 `/sim/wheel/state` 实际轮速；停止发布超过 100 ms 后车辆应停车。
4. 在 Dashboard 切换到 `active_steering_4wd`，发布四个驱动轮速度和两个前轮转向速度，确认实际转角方向、机械限位和四轮反馈。
5. 添加静态、移动障碍物并驾驶穿过其前后区域；在前后点云页和 Monitor 中确认两片点云随相对位置变化，且不会显示车辆自身点。
6. 依次应用 `flat`、`slope`、`golf_heightfield`；观察 RTK 主天线位置、基线 yaw 和 IMU roll/pitch 与车辆姿态变化一致。
7. 依次暂停/恢复、复位车辆、切换车型、切换场地和触发一次失败回滚；确认仿真时钟、话题状态、旧命令失效和 Dashboard generation 正确。
8. 断开命令 publisher，确认 Dashboard 进入断线/等待状态并停车；重启 publisher 后先保持静默，旧命令不得恢复，再发送一条新合法命令恢复运动。
9. 遍历 Dashboard 15 个默认页面，确认企业参数、轨迹/速度旧图、新接口曲线、前后点云和场景控制可见；确认接触力、接触点数、打滑和其他内部诊断默认隐藏，显式开启开发者诊断后才可见。
10. 确认 PyBullet 主窗和 Dashboard 覆盖主屏可用区域，Dashboard 宽度精确按 `33/100` 计算且 Main 取余，无重叠、越界或不可达控件。

只做键盘驾驶和视觉检查时使用 `--interface-mode local`；真实 eCAL 验收必须使用 `--interface-mode ecal`，不能用 local 模式替代。

## 7. PyBullet 关键机制说明

### 7.1 `getLinkState` 与坐标变换

传感器安装位不是直接写死为世界坐标。程序先用 `getLinkState()` 读取安装父 link 的世界位置和四元数，再把场景文件中的局部平移/旋转与父 link 位姿相乘，得到传感器世界位姿。RTK 主、副天线由两个不同局部安装点转换到世界坐标；两点连线的 `atan2(dy, dx)` 就是基线 yaw。车辆运动、切换车型或场地后都重新读取 link 状态，因此输出跟随真实刚体，而不是沿用旧世界缓存。

### 7.2 `rayTestBatch` 多线点云

每个 LiDAR 帧先在传感器局部坐标生成 2880 条水平角和垂直线组合，在扫描 deadline 读取一次安装位姿，并用一次 `rayTestBatch(numThreads=0)` 查询该发布时刻的世界。生产后端的 `ray_test_indexed_hits()` 立即丢弃 miss，只把“原射线索引 + 命中”交给点云层；预验证批量逆变换避免对同一批官方 PyBullet tuple 重复逐点校验。原射线索引仍决定 `line` 和 `offset_time_ns`，所以压缩 miss 不改变企业字段顺序。

点云在完整批次成功后才原子构造；Dashboard 使用同一批世界命中点和同一发布时刻读取的 `base_link` 位姿生成俯视图。第一版不跨物理帧拼接世界状态，`offset_time_ns` 只表达射线顺序，不模拟运动畸变。前后雷达仍错相 50 ms，消息时间戳严格保持 100 ms 周期。实时 eCAL 循环使用绝对 deadline、超期 `sleep(0)` 让出和 cyclic-GC 保护，退出时恢复调用方原 GC 状态。

### 7.3 碰撞 group/mask

地形、车辆和可被 LiDAR 看到的障碍物使用不同碰撞位。物理接触 mask 决定哪些刚体互相碰撞，LiDAR mask 决定射线允许看到哪些 body。车辆自身不在 LiDAR 可见组中，所以点云不会把传感器载体误当障碍物；地形探测射线只看地形组，所以车辆或障碍物盖住采样点时也不会被误判为地面。

### 7.4 主线程隔离

PyBullet 的 body 创建、删除、关节命令、`stepSimulation()`、关节/位姿读取和射线调用都留在物理主线程。eCAL 回调只复制并校验 Protobuf 命令，写入带代际的 mailbox；日志线程只消费不可变记录；Qt 只读取不可变 Dashboard 快照。这样可以避免 eCAL、日志或 GUI 线程在物理世界重建时持有失效 body id，也使暂停、回滚和关闭顺序可测试。

## 8. 已知限制与残余风险

- RTK 和 IMU 是无噪声真值，不模拟卫星遮挡、差分解算、漂移、偏置或温度误差。
- 点云按发布时刻一次采样，不模拟 MID-360 的真实扫描规律、运动畸变、回波强度、光电畸变、雨雾、草叶或电子噪声。
- `local` transport 只用于进程内调试和键盘驾驶，不是正式 eCAL，也不能作为跨进程验收替代品。
- 当前主机未安装 eCAL Monitor 桌面程序；用户人工 Monitor 验收仍需补充该外部工具。
- eCAL 可选系统时间插件未安装；当前接口使用统一仿真时间戳，不提供跨主机硬件时间同步保证。
- 本次获授权的 post-fix 真实 eCAL 执行在 discovery 前被 Codex 沙箱的 socket 权限阻断，P0 仍无有效 post-fix 结论；修复前独立安静运行的 wheel drop、早期旧 PASS、并发污染失败和本次环境阻断都不能证明当前版本。下一次有效复验需重新授权并使用允许 eCAL socket 的环境，继续保留 95 Hz 门槛和完整原始证据。
- 历史 schema v3/17 页 GUI 自动门禁曾证明窗口、控件、非空绘制和持续驾驶链路；当前 schema v4 只有纯测试证据，四组真实 X11/Xvfb 门禁仍待补。即使自动门禁后续通过，点云观感、车体动作和数据是否符合用户业务预期仍需人工判断。
- 当前正式 GUI oracle 已在纯测试中独立证明根布局、两个 pane 共同铺满剩余高度、canvas/page 与 axes/canvas 覆盖率，并覆盖 DPR `1/1.25/2` 的精确边界；四组 schema v4 真实 X11/Xvfb 门禁仍因当前环境阻断而待补，纯测试不能替代实机结果。
- measurement-start 屏障当前显式排空出站 lane，但没有单独等待 transport 入站 callback 归零；外层正式仿真时间窗及原始日志/peer 精确序列比较会阻止整体假通过，仍建议后续补入站跨 ACK 的阻塞回归。
- RTK 局部 log-chain helper 当前先验证 `peer - log`；外层六话题原始日志/peer 精确序列比较继续验证反向差集并阻止额外帧假通过，后续可把双向集合检查下沉到该 helper 并补局部测试。
- 阶段四导航、自动刹停、路径规划和动态避障尚未实现；阶段三不会提前加入这些行为。
