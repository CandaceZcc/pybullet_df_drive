# 阶段二 Dashboard 动态场景与障碍物设计

## 1. 目标与范围

阶段二在阶段一四种车型、三类场地、运行期切换和固定侧边栏已经稳定的基础上，增加可复现的静态/移动障碍物，并按真实共享状态提取场景协调边界。

本阶段交付：

- 箱体、圆柱体和球体静态障碍物。
- 沿贴地直线路径往返的运动学障碍物。
- 静态、移动及混合比例追加生成，同一前置状态下支持随机种子复现。
- Dashboard 障碍物列表、删除选中和清空全部。
- 车型切换、车辆复位、场地重建与障碍物恢复的统一事务。
- 阶段一驾驶、相机、绘图、车型/场地切换和 240 Hz 物理循环回归保护。

本阶段不实现 eCAL、前后多线雷达点云、双天线 RTK、企业 IMU、自动刹停、路径规划或自动避障。自动导航能力明确列入阶段四，阶段二只提供可碰撞、可被射线命中的动态场景基础。

## 2. 已确认的产品语义

### 2.1 场地与车型切换

- 车型切换和车辆复位保留全部障碍物。
- 场地切换保存障碍物逻辑快照，保持形状、尺寸、XY、逻辑 ID、运动路径、路径进度和运动方向，仅根据目标地形重新计算高度与姿态。
- 若目标地形不能完整容纳并恢复原障碍物布局，则目标场地事务失败，恢复旧场地、车辆及障碍物快照。
- PyBullet body ID 是可重建的运行标识，不作为 Dashboard 或事务恢复依据。

### 2.2 添加与删除

- “随机添加”采用追加语义，不隐式替换已有障碍物。
- 模式支持静态、移动和混合；混合模式默认移动比例为 30%。
- 数量换算采用确定性取整；移动比例大于零且总数足够时，至少产生一个移动障碍物。
- 在相同场地、相同已有障碍物状态和相同参数下，相同种子生成相同结果。复现完整初始布局时，先清空再用相同参数添加。
- Dashboard 通过列表单选逻辑 ID，再执行“删除选中”；不在阶段二实现 PyBullet 3D 视窗鼠标拾取。

### 2.3 移动行为

- 移动路径是随机起点与终点之间的直接线段，不是机器人导航或绕障路径。
- 平面、斜面保持直线运动；高尔夫场地保持 XY 直线投影，并随地表更新 Z 与法向。
- 障碍物到端点后反向，不瞬移、不越界、不无故停顿一帧。
- 移动障碍物是质量为零、由管理器每帧更新位姿的运动学刚体。车辆碰撞不能改变其路径，但障碍物仍能阻挡或推动受到动力学模拟的车辆。
- 生成阶段检查完整运动走廊，避免路径穿过出生保护区、已有障碍物或其他移动路径。

## 3. 架构与职责

```text
Dashboard 操作与驾驶命令
            |
            v
SimulationCoordinator
    |-- ActiveManualWorld
    |     |-- SceneInfo / TerrainSelection
    |     `-- ActiveManualRobot
    `-- ObstacleManager
          |-- 障碍物逻辑记录与快照
          |-- 随机规划与空间校验
          |-- PyBullet 刚体生命周期
          `-- 每物理帧运动更新
```

### 3.1 `SimulationCoordinator`

协调器在物理主线程中串行处理车型、场地、复位、添加、删除和清空操作。它持有现有 `ActiveManualWorld` 与 `ObstacleManager`，但不在阶段二提前引入完整 `SimulationBackend`、eCAL 或传感器抽象。

主要职责：

- 每个物理帧最多处理一个结构性操作。
- 场景重建前停止车辆命令，切换完成后同步 Dashboard 状态。
- 车型切换只替换车辆，保留障碍物管理器与现有刚体。
- 场地切换快照障碍物逻辑状态，在目标场地重新实例化；失败时重建旧世界与障碍物。
- 向 Dashboard 输出只读障碍物快照和操作结果，不把可变管理器或 PyBullet 对象暴露给 Qt。

### 3.2 `ObstacleManager`

管理器保存稳定逻辑状态：

- 逻辑 ID、临时 body ID、模式、形状、尺寸、颜色和当前位姿。
- 移动障碍物的路径端点、路径进度、方向和速度。
- 当前场地引用、边界和已占用空间。

管理器提供批量规划、批量创建、单个删除、全部清空、快照、恢复和逐帧更新。批量添加先规划整批，再创建刚体；任一创建失败时删除本批已经创建的 body，原有逻辑集合不变。较大的添加和清空操作由可恢复的跨帧任务执行，不能在一个物理帧中完成全部随机搜索或暂存 body 创建。

### 3.3 地表采样边界

`ObstacleManager` 复用并扩展 `scene.py` 现有公开的 `probe_terrain()`，使调用方可传入 `SceneInfo.body_ids` 并只接受地形 body 的射线命中。过滤实现必须能跳过车辆、障碍物自身及其他障碍物，不能把障碍物顶面误认为地面，造成逐帧爬升。障碍物代码不直接导入私有射线函数；若姿态计算需要补充公开辅助函数，只补充法向与路径朝向组合所需的最小接口。

## 4. 生成与运动算法

### 4.1 生成请求

每次添加包含：模式、形状、数量、随机种子、移动速度和移动比例。形状在一个批次内固定，模式可按混合比例拆分。混合模式的移动数量使用 `floor(count * ratio + 0.5)` 四舍五入；当 `count >= 2` 且比例在 `(0, 1)` 内时，再夹紧到 `[1, count - 1]`，因此 5 个、30% 得到 2 个移动，10 个、30% 得到 3 个移动。尺寸从代码配置层的稳定范围中按种子生成，不把质量、摩擦、颜色或详细尺寸放进 Dashboard 主界面。

初版输入保护为每批 1–50 个、场景总计不超过 100 个。达到上限或有限次候选采样后仍无法找到合法布局时，整批失败并返回明确原因。

### 4.2 空间校验

候选位置必须同时满足：

- 障碍物完整外接占地位于 `TerrainBounds` 内。
- 与车辆出生点的距离大于保护半径。
- 与提交时车辆所有 link 的合并 AABB 保持安全裕量，不能在正在驾驶的车辆内部或紧邻车体生成。
- 与全部已有及本批障碍物保持最小间距。
- 只命中当前 `SceneInfo.body_ids` 中的地形，底部按局部高度和法向贴地。
- 移动障碍物的完整扫掠走廊满足上述边界与间距条件。

所有随机行为使用请求局部随机数生成器，不修改 Python 或 NumPy 全局随机状态。候选遍历、模式分配和逻辑 ID 分配顺序必须稳定，保证测试和重建可复现。

### 4.3 逐帧运动

移动障碍物按 `speed * dt` 推进 XY 路径进度。跨过端点时夹紧端点、翻转方向并继续消费剩余位移，使较大 `dt` 或高速下仍不越界。每个新位置先以限定地形 body 的射线重新采样高度和法向，再在 `stepSimulation()` 前更新位姿与路径切向速度。初版使用质量为零的刚体和受控的小步位移；正式开发的第一项门禁是最小 DIRECT 碰撞可行性测试。测试要求障碍物路径横向误差不超过 `1e-6 m`、接触穿透不超过 `0.03 m`，碰撞期间车辆线速度不超过 `3.0 m/s`、角速度不超过 `10.0 rad/s` 且所有状态有限；在相同初态、命令和时长下，静态障碍场景的车辆前进位移不得超过无障碍基线的 50%。任一判据不满足时停止后续 Dashboard 开发，回到运动学碰撞机制评审。

### 4.4 跨帧结构操作

添加操作分为“候选规划、隐藏且禁用碰撞的 body 暂存、提交激活”三个阶段；清空和大批删除也分批处理。规划和暂存阶段每个物理帧的软预算为 2 ms，超出后立即让出控制，继续处理 Qt 事件、驾驶命令和物理步进。提交激活前再次检查当前车辆 AABB；车辆已经进入候选区域时，整批撤销并提示重新添加。

批次原子性指 Dashboard 逻辑列表只在整批成功后一次发布，暂存 body 不可见且不参与碰撞。最终激活允许集中在一个提交帧完成，但该帧必须满足 100 ms 事件间隔硬门禁；若 50 个 body 无法满足，则停止并重新评审激活机制，不能把半批对象发布为成功。2 ms 跨帧配额使用可注入时钟做确定性单元测试，真实 100 ms 上限只在项目验收机集成测试中判定，避免 CI 负载导致误报。

自动验证记录结构操作期间的最大物理步间隔和 Dashboard 事件间隔；阶段二目标为普通连续帧不持续超过 20 ms、任何单次操作造成的事件间隔不超过 100 ms。若项目验收机上规划或暂存阶段无法满足，优先减小每帧工作配额，不降低已确认的每批 50、场景 100 输入上限；若最终提交帧超过硬门禁，则回到设计评审。

## 5. Dashboard 设计

### 5.1 顶部障碍物页

420 px 固定侧边栏的顶部标签页新增“障碍物”页，使用单选表格展示逻辑 ID、模式、形状和 `x/y/z` 位置。表格按 Dashboard 刷新频率更新，不按物理频率重绘；刷新与场地重建后按逻辑 ID 恢复选中状态。

### 5.2 下方障碍物控制组

下方可滚动控制区新增“障碍物”组：

- 模式、形状、数量、种子、移动速度、移动比例。
- 随机添加、删除选中、清空全部。
- 最近一次操作状态或失败原因。

静态模式禁用速度和比例；移动模式启用速度、禁用比例；混合模式同时启用。未选择表格行时禁用删除按钮。清空立即作为队列命令提交，不打开阻塞物理循环的模态对话框。

### 5.3 命令和快照

Dashboard 只产生带类型的结构性操作并进入 FIFO 队列。协调器每帧取一个操作执行并返回结果；普通障碍物增删不清空驾驶命令，车型或场地重建仍执行安全停车。操作期间相关控件显示忙碌状态，完成后用只读快照刷新表格。

每次添加、删除、清空、场地重建、回滚及其结果写入独立的障碍物 JSONL 事件日志，至少记录仿真时间、逻辑 ID、参数、种子、车型、场地和错误原因。阶段二提供场地事务所需的内存快照；包含阶段三传感器安装信息的完整场景文件导出/加载延后到阶段三统一完成。

## 6. 错误处理与事务保证

- 参数非法、数量超限或无法规划整批时，不创建任何 body。
- PyBullet 创建中途失败时，只回收本批新 body。
- 删除不存在的逻辑 ID 返回可显示错误，不影响其他障碍物。
- 场地切换恢复失败时，重建旧场地、旧车辆和障碍物快照；若回滚本身失败，抛出包含目标错误与回滚错误的致命异常。
- 所有操作结果包含用户状态文本和可测试的错误信息，Dashboard 不自行推断操作是否成功。

## 7. 验证与验收

### 7.1 自动化测试

1. 纯规则测试：种子复现、明确的混合比例取整、边界/间距/出生区/当前车辆 AABB、走廊校验、端点反向和批次原子性。
2. 地表过滤测试：车辆、障碍物自身或其他障碍物位于射线上方时，采样仍只返回 `SceneInfo.body_ids` 中的地形高度和法向。
3. PyBullet DIRECT 测试：三种碰撞形状、质量为零、三类场地贴地、射线命中、运动更新、删除和清空；移动障碍物与车辆接触时验证车辆受阻、穿透上限、冲量稳定和障碍物轨迹不偏移。
4. 协调器测试：车型/复位保留障碍物、场地重建保留逻辑状态、失败整体回滚、命令顺序、跨帧任务、提交前 AABB 复验及无重复 body。
5. Dashboard 离屏测试：控件启用状态、命令队列、表格选择保持、忙碌/错误状态和按钮行为。
6. 日志测试：添加、删除、清空、重建和回滚事件完整记录种子、逻辑 ID、场地及结果。
7. 性能测试：记录 50 个批量添加和 100 个清空期间的物理步与 Qt 事件最大间隔，并按 2 ms 工作配额验证操作会跨帧让出控制。
8. 回归测试：阶段一车型、场地、驾驶、键盘、相机、绘图、固定侧边栏及全量测试继续通过。

### 7.2 GUI 人工验收

- 混合模式添加 10 个障碍物，默认得到 7 个静态和 3 个移动。
- 清空后用相同场地、参数和种子重新添加，形状、尺寸、位置和运动初态可复现。
- 通过表格选择逻辑 ID 删除单个障碍物，其他对象不受影响；清空移除全部对象。
- 移动障碍物连续贴地运动、在端点反向，与车辆碰撞后仍保持路径。
- 切换车型或复位车辆时障碍物不变；切换三类场地后逻辑布局不变且重新贴地。
- 持续驾驶期间追加、删除、切换场地和切换 Dashboard 页面，无明显卡顿、断控或焦点丢失。

### 7.3 阶段停止门禁

阶段二自动验证完成后，启动独立审查线程，从需求完整性、逻辑正确性、边界情况、代码质量、测试覆盖和实际运行结果六方面审查。修复发现的问题并复验后，提交阶段二报告、GUI 操作步骤和已知问题，然后停止开发，等待用户人工验收；不得提前实施阶段三或阶段四。

## 8. 开源参考边界

- 参考 Bullet `createObstacleCourse.py` 的基础碰撞形状与运行时刚体创建方式。
- 参考仓库内 `references/repos/pybullet_sim` 的环境构造、障碍物射线命中和传感器组织方式。
- 不直接复制参考仓库的单文件演示结构；本项目必须保留逻辑状态、事务回滚、确定性生成和 Dashboard/物理线程隔离。

## 9. 后续阶段四边界

阶段四在阶段三传感器和 eCAL 接口验收后开始，负责障碍物感知与紧急刹停、地图或代价地图、全局路径规划、局部动态避障、导航控制和安全状态机。阶段二障碍物的直线往返路径仅是场景行为，不代表车辆导航路径。
