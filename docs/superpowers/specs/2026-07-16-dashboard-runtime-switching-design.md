# Dashboard 运行时切换车型与场地设计

> 设计日期：2026-07-16  
> 设计状态：已实现并通过自动验证，等待用户 GUI 人工验收

## 1. 目标

在 `--gui --manual` 模式中，允许用户不退出仿真程序，先在 Dashboard 选择车型或场地，再通过“应用车型”或“应用场地”按钮显式执行切换。

本次交付覆盖：

- 在四种已注册车型间切换。
- 在 `flat`、`slope`、`golf_heightfield` 三种已注册场地间切换。
- 在 Dashboard 修改斜面坡度、高尔夫随机种子和起伏等级。
- 切换时安全清零命令、重建必要的 PyBullet 对象、清理旧遥测历史并恢复相机跟随。
- 切换失败时恢复上一个有效世界，并把错误显示在 Dashboard。

本次不实现障碍物管理、eCAL、传感器扩展或自动驾驶，这些仍按原需求阶段独立交付。

## 2. 方案选择

采用“Dashboard 发出一次性请求，手动仿真主循环执行切换”的方案。

Dashboard 只负责采集待应用参数和显示结果，不在 Qt 按钮回调中调用 PyBullet。所有世界对象的创建、删除和恢复都留在已有手动仿真线程中，避免 Qt 事件线程与 PyBullet 客户端并发访问。

暂不引入完整 `SimulationCoordinator`，因为当前只有车型和场地两类切换，现有 `manual_demo.py` 已经拥有场景、车辆、控制循环和日志对象。等阶段二加入障碍物后，再根据实际共享状态抽取协调器。

## 3. Dashboard 交互

参数区增加两个明确分组：

### 3.1 车型

- `车型` 下拉框列出 `robot_model_names()` 返回的四种车型。
- “应用车型”按钮把当前下拉框值封装成一次性车型切换请求。
- 只改变下拉框不会修改仿真世界。
- 请求被主循环读取后立即消费，后续帧不会重复触发。

### 3.2 场地

- `场地` 下拉框列出 `terrain_model_names()` 返回的三种场地。
- `坡度` 数值框用于 `slope`，单位为度。
- `高尔夫种子` 整数框和 `起伏等级` 下拉框用于 `golf_heightfield`。
- Dashboard 根据待应用的场地类型启用相关参数，其他参数保留但禁用。
- “应用场地”按钮把场地类型及其参数封装成一次性场地切换请求。
- 用户修改高尔夫种子后再次应用，即可生成另一份可复现地形。

### 3.3 状态反馈

- Dashboard 显示最近一次切换状态：就绪、应用中、成功或失败。
- 成功后，控件中的当前选择与实际活动世界保持一致。
- 失败后，控件恢复为上一个有效选择，并显示简短错误信息。
- 车辆复位按钮仍只重载当前车型，不改变当前场地参数。

## 4. 请求与活动状态

Dashboard 命令在现有速度、退出和复位字段之外，增加两个可选的一次性请求：

- 车型请求：目标 `robot_model`。
- 场地请求：目标 `terrain_model`、`slope_deg`、`golf_seed`、`golf_relief`。

手动仿真循环维护独立的活动状态，不能继续把启动时 `ExperimentConfig.robot_model` 和 `ExperimentConfig.terrain_model` 当作运行期真值。活动状态至少包含：

- 当前 `ActiveManualRobot`。
- 当前 `SceneInfo`。
- 当前场地选择参数。

遥测和日志始终使用活动状态中的车型和场地，而不是启动配置中的旧值。

## 5. 切换事务

### 5.1 应用车型

1. 当前帧先把线速度和角速度命令清零。
2. 使用当前场地出生点尝试加载目标车型，并应用现有摩擦和电机参数。
3. 新车型成功加载后删除旧车型；在下一次物理步进前不会让两个重叠车辆共同参与仿真。
4. 更新活动车型，清空越界锁存、命令斜坡、Dashboard 平滑值和实时曲线。
5. 如果加载失败，删除可能产生的半成品，保留旧车型并显示错误。

目标车型与当前车型相同时不重载，只报告当前车型已生效。

### 5.2 应用场地

`create_slope_scene()` 当前会调用 `resetSimulation()`，所以应用场地是一次完整世界重建事务：

1. 在重置前保存当前车型名称和上一个有效场地选择。
2. 清零车辆命令并暂停本帧物理步进。
3. 重置 PyBullet 世界，创建目标场地，再从目标场地安全出生点加载当前车型。
4. 成功后更新活动场景和车辆，重新应用 GUI 可视化设置，清空越界锁存、命令斜坡和 Dashboard 历史。
5. 如果目标世界创建失败，再次重置世界，并用保存的有效选择重建旧场地和旧车型。
6. 回滚成功时继续运行并显示原始错误；回滚也失败时停止手动仿真并抛出包含两个错误原因的异常，避免在无地面状态继续步进。

目标场地及全部参数与当前活动选择完全相同时不重建，只报告当前场地已生效。修改坡度、随机种子或起伏等级后，即使场地类型相同也必须重建。

## 6. 控制、相机与日志语义

- 车型或场地切换帧不执行旧速度命令。
- 切换后的下一帧从零命令重新经过现有加速度限制器。
- 相机跟随在重建后使用新车辆 `body_id`；固定相机重新应用启动配置。
- 仿真步号和遥测时间保持连续，不因切换归零。
- CSV 保持为同一个手动运行会话；每行现有的 `robot_model` 和 `terrain_type` 字段记录切换前后的实际对象。
- Dashboard 曲线在成功切换或回滚重建后清空，避免把不同坐标原点下的轨迹连接成错误直线。

## 7. 错误处理与输入约束

- Dashboard 只能提交注册表中存在的车型和场地。
- 坡度、随机种子及内部数值在进入 PyBullet 前必须为有限值，并复用现有配置约束。
- 切换请求处理函数返回明确的成功状态和用户可读消息，Qt 界面不直接吞掉异常。
- 重建失败不得留下活动状态指向已被 `resetSimulation()` 删除的旧 `body_id`。
- 退出请求优先于切换请求；同一帧同时出现复位和切换时，场地切换优先，其次车型切换，最后普通车辆复位，确保最多执行一次重建。

## 8. 测试与验收

自动测试按测试驱动顺序覆盖：

- Dashboard 只有点击应用按钮才产生一次性请求。
- 场地类型变化时相关参数控件正确启用和禁用。
- 车型切换保留场地并替换 PyBullet 车辆 `body_id`。
- 三种场地间的切换会替换地形和车辆，并保持当前车型。
- 同类场地参数改变会触发重建，完全相同的选择不会重建。
- 切换帧命令为零，历史曲线、平滑状态和越界锁存被清空。
- 目标场地创建失败时能恢复旧场地和旧车型。
- 四车型乘三场地的既有自动验证矩阵继续通过。

GUI 人工验收至少检查：

1. 在 Dashboard 中依次应用四种车型，确认窗口不退出、车型外观和反馈同步变化。
2. 依次应用平地、斜面和高尔夫场地，确认车辆出现在安全出生点。
3. 修改坡度并重新应用斜面，确认场地角度改变。
4. 修改高尔夫种子并重新应用，确认起伏改变；恢复旧种子后地形可复现。
5. 只修改下拉框但不点击应用，确认仿真世界不改变。
6. 每次切换后重新驾驶，确认控制、相机、复位和日志仍然工作。
