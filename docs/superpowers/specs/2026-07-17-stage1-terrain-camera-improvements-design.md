# 阶段一地形与相机跟随改进设计

> 设计日期：2026-07-17
> 设计状态：Task6自动验证已完成；GUI人工验收待用户完成

## 1. 背景与诊断

阶段一 GUI 预验收反馈包含四项：

1. 确认 `active_steering_4wd` 的四个驱动轮是否真实参与驱动。
2. 现有 `slope` 是一整块倾斜长方体，没有“平地进入斜面”的姿态变化，且默认前进方向表现为上坡。
3. 相机跟随底层函数已存在，但通用 GUI 配置默认关闭，常用启动命令和 Dashboard 都没有可发现入口；现有 `front` / `side` 只使用固定世界 yaw，不随车头旋转。
4. 现有高尔夫 heightfield 只有少量低频正弦和高斯小丘，层次和局部地形语义不够明显。

四驱的可复制 DIRECT 诊断、关节顺序、`getJointState()` 字段和本轮输出统一记录在[交付报告的主动转向四驱逐关节诊断](../../阶段一交付报告.md#主动转向四驱逐关节诊断)。该处是四驱物理证据的唯一复现入口。

## 2. 目标与非目标

### 2.1 目标

- 用可重复验收的三段式场地替换整体倾斜平面：高位平地、指定角度下坡、低位平地。
- 保持 `slope_deg` 为唯一斜面业务参数，用户在 Dashboard 修改后重新应用即可生效。
- 提高高尔夫场地的可视层次和地形变化，同时保持连续、可驾驶、可复现。
- 让相机跟随在 Dashboard 中可发现、可开关、可切换视角，并在车型/场地切换后继续使用新车体。
- 继续保护主动转向四驱的四轮实际反馈。

### 2.2 非目标

- 不增加障碍物、沙坑材质、草地材质、软土或地形变形，这些不属于本次阶段一补充。
- 不增加多段独立坡度参数，不改变现有场地枚举。
- 不引入外部 mesh、新纹理资源或新依赖。
- 不把 PyBullet debug camera 扩展为企业视觉传感器。

## 3. 总体方案

保留现有三个场地入口，按场地特性选择最小可验收实现：

- `flat`：保持单个水平静态长方体。
- `slope`：使用三个精确对接的静态长方体组成上平地、下坡和下平地。
- `golf_heightfield`：保留单个程序化 heightfield，增强高度生成函数。

`SceneInfo.body_ids` 已能表示多个地形刚体，所以三段式斜面不需要新场景协调器。地形探测继续通过 raycast 读取真实碰撞高度和法向，不用人工分段公式伪造传感结果。

## 4. 三段式下坡

### 4.1 几何与行驶方向

车辆统一从高位平地朝世界 `+X` 方向行驶：

1. 高位平地：长 `4 m`，宽 `12 m`。
2. 下坡段：沿坡面长 `8 m`，宽 `12 m`，角度为 Dashboard/CLI 中的 `slope_deg`。
3. 低位平地：长 `6 m`，宽 `12 m`。

斜面水平投影为 `8 * cos(slope_deg)`，高差为 `8 * sin(slope_deg)`。上下平地的表面高度与斜面两端一致。接缝使用很小的水平重叠防止数值缝隙，但不产生可见台阶。

车辆出生在高位平地中部，出生姿态水平。这样车辆需要先在平地行驶，再出现入坡 pitch 变化，经历稳定下坡，最后在低位平地回正。

### 4.2 边界与特殊值

- `slope_deg = 0`：三段表面高度相同，仍是有效的连续场地。
- 正坡度：沿 `+X` 方向下坡，符合本次 GUI 验收语义。
- 负坡度：保留现有数值能力，沿 `+X` 方向变为上坡；界面状态仍显示用户输入的负值。
- 场景 bounds 覆盖三段地形的水平投影；探测和越界保护不把合法的下坡终点误判为出界。

## 5. 高尔夫多尺度地形

### 5.1 高度组成

每个高度样本由下列连续分量叠加：

- 大尺度低频波：建立整体起伏和横坡。
- 中尺度椭圆高斯丘：提供方向不同的丘陵。
- 中尺度负高斯分量：形成浅洼，不生成垂直坑壁。
- 小尺度低振幅波：增加局部层次，但受最大局部坡度限制。
- 驾驶廊道：沿一条平滑曲线适度减弱局部丘洼和小尺度波，保留大部分低频丘洼与横坡，不形成直线平路。

所有随机位置、方向、尺度和相位都只由 `golf_seed` 生成。`low` / `medium` / `high` 继续控制总起伏幅度，同一种子和等级必须得到完全相同的高度数组。

### 5.2 安全与出生

- 继续使用连续函数，不向单个网格注入独立噪声。
- 出生点放在驾驶廊道起点，高度和法向仍通过 PyBullet raycast 获取。
- 四种车型必须继续通过静置接地、有限姿态、翻转、穿透、越界和短距离驱动检查。

## 6. Dashboard 相机跟随

### 6.1 交互

Dashboard 增加紧凑的“相机”分组：

- “启用跟随”复选框。
- “车后”、“侧面”、“固定”视角下拉框。

GUI 手动模式默认启用车后跟随。用户关闭后，程序不再每帧重置 debug camera，用户可以用 PyBullet 鼠标手动调整相机。视角变化在下一个物理帧生效，不需要“应用”按钮或场景重建。

### 6.2 跟随语义

- 车后：相机 target 为活动车体位置，相机 yaw 为车辆实际 yaw 加车后视角偏移。
- 侧面：相机 target 为活动车体位置，相机 yaw 为车辆实际 yaw 加侧视偏移。
- 固定：相机 target 仍跟随车辆位置，yaw 始终使用 `camera_yaw`，不随车头旋转。

相机高度、俯仰角和距离继续使用现有 `camera_pitch` 和 `camera_distance`。场地或车型切换后，主循环只从更新后的 `ActiveManualWorld` 读取车体 `body_id`，不保留已删除车体引用。

### 6.3 配置兼容

保留现有 `camera_follow_enabled`、`camera_follow_view`、`camera_distance`、`camera_yaw` 和 `camera_pitch` 字段。

- 现有 `front` 映射到 Dashboard 的“车后”追踪语义。
- 现有 `side` 映射到“侧面”。
- 现有 `custom` 映射到“固定”。

这样现有 YAML 不会因枚举改名失效。默认配置改为启用 `front`，使 GUI 手动入口默认就能看到跟随效果。

## 7. 状态流与错误处理

1. Dashboard 每帧在 `DashboardCommand` 中返回当前跟随开关和视角，它们是持续状态，不是一次性场景请求。
2. 手动物理循环完成当前帧状态读取后，如果开启跟随，用活动车体的最新位置和姿态更新 debug camera。
3. Dashboard 不可用时，使用启动配置中的开关和视角，不影响 PyBullet debug slider 驾驶兜底。
4. 车型和场地切换继续使用现有事务与回滚路径；地形构造失败不得留下部分三段场地。
5. 相机更新只在 GUI 主线程调用 PyBullet，Dashboard Qt 回调不直接访问物理客户端。

## 8. 测试与验收

### 8.1 自动测试

按 TDD 顺序增加以下回归：

- 主动转向车在真实 PyBullet DIRECT 中的四个驱动关节均有接近目标的实际轮速，四轮字段持续进入遥测。
- `slope` 返回三个地形 `body_id`，出生点法向水平，坡面中点法向匹配 `slope_deg`，低位平地法向重新水平。
- 上平地高度高于下平地，两条接缝附近 raycast 不丢失、不产生超出容差的高度跳变。
- 四种车型能从高位平地进入下坡，全过程位姿有限、不翻车、不越界，并产生先水平、后下俯、再回正的 pitch 趋势。
- 高尔夫高度数组完全可复现，不同种子产生不同数组，起伏等级仍按预期改变高差。
- 多尺度地形同时包含多个局部高点和低点，驾驶廊道的小尺度粗糙度低于廊道外区域，最大相邻网格高差不超过车辆回归门槛。
- Dashboard 正确暴露跟随开关和三种视角，并在命令中持续返回当前状态。
- 车后和侧面相机 yaw 随车辆 yaw 等量改变；固定视角保持配置 yaw。
- 车型/场地切换后，跟随使用新车体 `body_id`，关闭跟随时不调用相机重置。
- Task5 的 `5`、`3`、`184` 项聚焦证据保留在交付报告中；Task6 fresh 全量 pytest 为 `224 passed in 10.81s`，4 × 3 DIRECT 矩阵通过，GUI 人工验收待用户完成。

### 8.2 GUI 人工验收

1. 选择 `slope` 并应用正坡度，确认车辆出生在上方平地，向前驾驶依次经历平地、入坡、稳定下坡和低位平地。
2. 切换四种车型，确认都能在上平地安全出生并驶入坡面。
3. 对主动转向车前进并转弯，确认 Dashboard 的四轮实际轮速都变化，两个前轮转角都变化。
4. 对同一高尔夫种子重复应用，确认丘陵、浅洼和驾驶廊道完全一致；修改种子后局部结构变化。
5. 切换相机的车后、侧面和固定视角，确认转弯时前两者随车头旋转，固定视角不旋转。
6. 关闭跟随，用 PyBullet 鼠标调整相机，确认不会在下一帧被程序抢回。
7. 在跟随开启时切换车型和场地，确认相机自动跟随新车，无跳回已删除车体的情况。
