## 1. 目标与现状

阶段五处理五项现场问题：MID-360 地形显示稀疏、采集目录命名和 Viewer 自动导入失效、Dashboard 缺少内嵌 3D 点云、五路 eCAL 状态为空、真实遥控器尚未接入。本文记录的是待实现合同，不能作为阶段五已经完成的证明。

当前可确认的事实如下。

| 编号 | 现象 | 已确认原因 | 处理方向 |
|---|---|---|---|
| R1 | 单帧点云难以辨认坡面 | MID-360 实时帧保持 10 Hz、每帧 5,760 个 firing slot；截图中的 100 ms 帧只有 1,976 个有效命中点 | 保留官方非重复点阵，以带位姿的多帧累积、衰减和着色提高地形可读性 |
| R2 | 导出目录呈 UUID | `slope_sim/manual_capture.py` 使用 `capture-{uuid4().hex}` | 全部人工采集统一使用本地时间目录名，并处理同秒冲突 |
| R3 | 点击导入后只启动 Viewer 或停在文件对话框 | 自动化依赖 `xdotool` 和固定 1600×900 坐标 | 取消固定坐标依赖，按完整播放状态判定成功 |
| R4 | “打开实时点云”没有 Dashboard 内嵌 3D 画面 | 当前路径启动外部 ROS Bridge 与 RViz2；Dashboard 只有二维投影 | Dashboard 新增 eCAL subscriber、3D OpenGL 视图和只读诊断终端 |
| R5 | eCAL 未连接，状态和折线图为空 | 用户命令包含 `--no-interface`；本机还缺少 `ECAL_CONFIG_PATH` 与 `ECAL_TIME_PLUGIN_PATH` 指向的正式运行资源 | 正式启动注入受控 eCAL 环境，预检给出缺失项和恢复命令 |
| R6 | 真实遥控器未接入 | 附件代码直接使用 `/dev/ttyUSB2`，未接入 v2 Command authority，缺少失联保护 | 扫描稳定串口链接，解析有效帧，通过唯一 Command 发布者控制仿真 |

阶段五不修改 MID-360 官方扫描方向，不用规则网格补点，不降低 10 Hz 发布频率，也不把附件 `mower_base.cpp` 直接编入生产程序。FAST-LIO、回环优化和真实 Livox 硬件驱动不在本阶段范围内。

## 2. 总体架构

```text
                         runSim / release environment
                    ecal.yaml + time plugin + descriptor
                                      |
                                      v
+-------------------+       +-------------------------+
| PyBullet Simulator|<------| C++ Command authority   |
| physics + sensors | 100 Hz| sole eCAL command writer|
+---------+---------+       +-----------+-------------+
          |                                 ^
          | wheel/lidar/rtk/imu             | local controlled IPC
          |                                 |
          v                         +-------+--------+
  eCAL v2 data plane                | input arbiter  |
          |                         | remote/keyboard|
          |                         +-------+--------+
          |                                 ^
          |                                 |
          |                         +-------+---------+
          |                         | serial RC worker|
          |                         | scan/decode/WDT |
          |                         +-----------------+
          |
          +--------------------------+---------------------------+
                                     |
                                     v
                          +------------------------+
                          | Dashboard              |
                          | telemetry + charts     |
                          | 3D cloud + eCAL console|
                          +-----------+------------+
                                      |
                         Qt queued signal/slot
                                      |
                    +-----------------+----------------+
                    | eCAL receive workers             |
                    | validation + latest-frame buffers|
                    +-----------------+----------------+
                                      |
                     Recorder -> Export -> LVX2/PCD/PLY
                                      |
                                      v
                              Livox Viewer 2
```

进程职责固定如下。

- Simulator 维护 PyBullet 世界和传感器采样，发布四路状态。
- Command authority 是 `/sim/wheel/command` 的唯一 eCAL publisher。遥控器、键盘和自动控制器只能向它提交候选命令。
- Dashboard 订阅五路 eCAL 数据并显示协议状态；进程内遥测单独标注，不能替代 eCAL 连通性。
- eCAL 回调只做数据复制和有界入队。Protobuf 校验、统计和点云整理在 worker 中执行；Qt 控件及 OpenGL 资源只由 GUI 线程更新。
- Recorder、Exporter、Viewer 使用同一会话身份和最近一次成功导出的绝对路径。

## 3. eCAL v2 数据合同

正式运行固定使用以下五个 topic。

| Topic | Simulator 方向 | 标称频率 | Dashboard 最少显示项 |
|---|---|---:|---|
| `/sim/wheel/command` | 订阅 | 100 Hz | producer 数、active source、sequence、租约年龄、v/w |
| `/sim/wheel/state` | 发布 | 100 Hz | peer 数、实测频率、sequence、轮速、车体速度、延迟 |
| `/sim/lidar/points` | 发布 | 10 Hz | peer 数、实测频率、sequence、点数、延迟、drop/error |
| `/sim/rtk/state` | 发布 | 10 Hz | peer 数、实测频率、sequence、三天线位置、heading |
| `/sim/imu/attitude` | 发布 | 10 Hz | peer 数、实测频率、sequence、roll/pitch、延迟 |

每条收到的数据都要校验 type name、descriptor SHA-256、simulation session、world generation、sequence 和时间戳。Dashboard 只把当前会话、当前 world generation、descriptor 匹配且 sequence 前进的数据标为“运行中”。错误 descriptor、旧会话帧、倒退或重复 sequence 应丢弃并计数。

状态名称统一为：`已禁用`、`等待 peer`、`接收中`、`数据超时`、`协议错误`。`--no-interface` 对应 `已禁用`，不能显示成网络故障。

## 4. P0 功能需求

### 4.1 正式启动与环境门禁

`runSim` 是阶段五正式入口。默认启动一个 PyBullet GUI 和一个 Dashboard GUI，接口模式固定为 eCAL。开发态等价命令为：

```bash
conda run -n slope-sim python main.py \
  --gui --manual --interface-mode ecal --drive-model physics \
  --robot-model df_mid --terrain-model slope --slope-deg 8
```

正式入口需要完成以下动作。

1. 从安装根定位并导出 `ECAL_CONFIG_PATH`、`ECAL_TIME_PLUGIN_PATH` 和 v2 descriptor 路径，不依赖用户当前目录或 Conda 激活状态。
2. 在创建 GUI 前验证配置文件、time-sync plugin、Python/C++ eCAL ABI、descriptor 摘要和 multicast/本机 transport 配置。
3. 失败时退出并打印缺失路径、检测值和一条可直接执行的恢复命令；Dashboard 已启动时同步显示同一原因。
4. 禁止 eCAL 模式静默回退到 local/v1。`--no-interface` 仅供无通信的 PyBullet 视觉检查，五路 eCAL 与 3D 实时点云在该模式下明确停用。
5. Simulator、Command 或 Dashboard 任一核心进程异常退出时，监管进程回收同一会话的其余子进程；Command 在回收前发布零命令。

### 4.2 Dashboard 五路数据和折线图

Dashboard 新增“eCAL v2”状态区，五个 topic 各占一行。行内显示方向、peer 数、实际频率、最后 sequence、drop/error、数据年龄、session 短标识、world generation 和 descriptor 状态。频率按至少 2 s 滑动窗口计算，进程启动后的首个窗口显示“采样中”。

现有数值和折线图必须绑定已验证的 eCAL 消息：

- 轮速、车体速度和命令曲线来自 WheelState/WheelCommand。
- LiDAR 点数、最近距离和延迟来自 LidarPointCloud。
- 位置与航向来自 RTK，姿态来自 IMU。
- 未收到数据时保留空值和原因，不用零值伪装有效数据。
- 曲线缓存按时间有界，默认保留 60 s；窗口最小化和 topic 中断不能导致缓存无界增长。

Dashboard 同时显示“进程内物理遥测”和“eCAL 对端数据”两组来源。两者数值可对照，但状态不能互相代替。

### 4.3 内嵌 3D 实时点云

Dashboard 底部增加可拖动的点云工作台。左侧使用 `pyqtgraph.opengl.GLViewWidget` 与 `GLScatterPlotItem` 显示三维点云，右侧或下方是只读 eCAL 诊断终端。项目已经锁定 PySide6、NumPy、pyqtgraph 和 PyOpenGL，本阶段不增加大型 3D 引擎。

点云接收链满足以下约束。

```text
/sim/lidar/points callback
        -> copy bytes
        -> bounded queue(capacity=1, replace stale frame)
        -> worker validates and decodes protobuf
        -> pose-at-sample transform into world coordinates
        -> temporal accumulation / render decimation
        -> Qt queued signal
        -> GUI-thread OpenGL update
```

1. 实时协议保持 10 Hz 和每帧 5,760 个 firing slot。渲染可抽样，原始消息、录制和导出不得抽样。
2. 默认显示最近 1.5 s 的有效命中点，时间窗可在 0.1 至 5.0 s 调整；超龄点按采样时间衰减并删除。
3. 多帧点必须按采样时刻的 `world -> lidar_link` 位姿变换后累积，车辆运动时不能直接叠加局部坐标，以免坡面拖影。
4. 提供语义、距离和高度三种着色模式。语义模式沿用 terrain `tag=1/reflectivity=100`、static obstacle `tag=2/160`、moving obstacle `tag=3/200`。
5. 显示坐标轴、地面网格、视角复位、点大小和时间窗控件。视图操作包括旋转、平移与缩放。
6. 工作台显示 topic、peer、Hz、sequence、本帧点数、累计点数、延迟和丢帧数。诊断终端按时间追加连接、校验、超时和恢复事件，最多保留 2,000 行。
7. worker 或 OpenGL 初始化失败时，Dashboard 保持运行并在工作台显示错误。关闭、重开点云面板不能重复注册 subscriber 或泄漏线程。
8. RViz2 保留为外部诊断工具；它的退出不影响 Dashboard 内嵌点云、Simulator 或 Recorder。

地形可读性以真实命中为基础。禁止修改官方 `slope_sim/assets/mid360_pattern.bin`，禁止插值生成伪点，禁止为了画面密度提高协议发射数。离线高保真路径继续使用每帧 20,000 个 firing slot，不与 5,760-slot 实时合同混用。

### 4.4 采集目录、原子导出与 Viewer

人工采集目录统一采用本地时间：

```text
capture-YYYYMMDD-HHMMSS
capture-YYYYMMDD-HHMMSS-01
capture-YYYYMMDD-HHMMSS-02
```

同秒首次采集不带后缀；冲突时从 `-01` 递增。目录名不能再出现 UUID。临时数据写入同一输出根下的临时目录，MCAP、PCD、PLY、LVX2 和 manifest 全部成功后执行原子改名。失败目录标记为未完成，不能覆盖“最近一次成功导出”。

“导入 Livox Viewer”使用最近一次成功导出的 LVX2 绝对路径。若当前会话尚无成功导出，按钮禁用并显示原因。自动化必须完成以下状态链：

```text
Viewer process started
  -> LVX2 file opened
  -> simulated MID-360 device selected
  -> playback started
  -> rendered point count > 0
```

固定屏幕坐标不属于可接受实现。优先使用 Viewer 可验证的命令行、窗口自动化接口或控件定位；确需桌面自动化时，按窗口和控件身份定位，并适配 DPI 与分辨率。日志中的 `ALvxKit::OpenLvxFile(<absolute path>) success` 只证明文件已打开，最终成功还需设备选择、播放状态和非零渲染三项证据。任何一步失败都应保留 Viewer 日志并在 Dashboard 给出失败阶段。

### 4.5 真实串口遥控器

用户附件原样保存在 `references/mower_base.cpp`，SHA-256 为 `2d57029fa068916e5c3dc3db639bbc08c95d963cd3fc1ec1cfd72ca265f109a6`。该文件用于确认串口协议和通道映射，不进入 release 编译输入。

已知协议如下。

| 项目 | 参考值 |
|---|---|
| 串口 | 115200 baud |
| 帧长度与帧头 | 25 byte，首字节 `0x0F` |
| 通道 | 16 个 11-bit channel |
| 标称校准范围 | `282..1722` |
| 实机有效输入范围 | `282..1772`（上端超出校准值时限幅，不丢弃整帧） |
| 解锁通道 | `ch6`，附件以 `1722` 判断 |
| 线速度 | `ch3 -> [-1.5, 1.5] m/s` |
| 角速度 | `ch1 -> [1.5, -1.5] rad/s` |

本机当前枚举出 FTDI FT4232H 的 `/dev/ttyUSB0` 至 `/dev/ttyUSB3`。实现时遍历 `/dev/serial/by-id/` 下的候选端口，在限定时间内按帧头、长度、16 通道范围和连续有效帧识别遥控器。`/dev/ttyUSB2` 只能作为诊断信息，不能写成默认设备身份。允许用户通过命令行显式指定稳定 by-id 路径。

串口 parser 需要保留跨 read 的残留字节，按 `0x0F` 重同步；一次 `read()` 的长度不能被当作一整帧。端口识别至少要求 2 s 内收到 20 个连续有效帧，且通道值在协议范围内。多个候选同时匹配时停止自动选择并列出候选路径。

遥控控制链遵循以下合同。

1. 串口 worker 只产生归一化输入和健康状态，经受监管本机 IPC 送入 Command authority。
2. `/sim/wheel/command` 始终只有一个 publisher。遥控 worker 不直接调用 PyBullet，也不创建第二个 eCAL publisher。
3. Dashboard 提供控制源选择：`键盘`、`遥控器`、`外部命令`。切换控制源先发送零命令；遥控器未解锁时不能接管。
4. `ch6` 使用可配置上阈值和回差判定解锁，默认上阈值 1600、下阈值 1400。附件中的精确相等判断仅作协议参考。
5. `ch1/ch3` 先按校准端点归一化，再应用可配置死区、方向和限幅。默认死区为满量程的 5%，最大线速度和角速度沿用 1.5。
6. 端口断开、连续无有效帧超过 100 ms、通道越界、parser 失步、解锁撤销、IPC 中断或 Command 租约过期时，Command authority 立即发布零命令并撤销遥控控制权。
7. 故障恢复后保持未接管状态，用户重新选择遥控器且 `ch6` 完成一次“未解锁 -> 解锁”沿后才允许运动。
8. Dashboard 显示设备 by-id、帧率、最后帧年龄、ch1/ch3/ch6 原始值、归一化 v/w、解锁状态、active source 和最近一次失效原因。

## 5. P1 需求

- 保存点云视角、点大小、时间窗和着色模式，下次启动恢复；损坏配置回到安全默认值并报告一次。
- 支持冻结当前 3D 帧和导出当前累计窗口的 PCD，文件放入当前 capture 目录并写入来源 session 与时间范围。
- 为遥控器提供校准向导，记录 ch1/ch3 的最小值、中位值、最大值和方向；校准结果写入用户配置，不修改系统级文件。
- 诊断终端支持按 topic 与严重级别过滤，并可导出当前会话的有界文本日志。

P1 不阻塞最初的功能联调，但最终 `.run` 交付前需要由用户确认保留、延期或删除。

## 6. 性能、资源与故障边界

| 项目 | 要求 |
|---|---|
| eCAL callback | 不解析大型点云，不等待 GUI，不阻塞 publisher |
| 点云队列 | 每个实时视图容量为 1，新帧替换未消费旧帧并累计 render drop |
| 3D 更新 | 目标 10 Hz；Dashboard 操作和窗口拖动保持响应 |
| 曲线缓存 | 默认 60 s，有界内存 |
| 点云累积 | 默认 1.5 s，最大 5 s；达到渲染上限时只对显示副本抽样 |
| 日志 | Dashboard 最多 2,000 行；文件日志按现有会话策略轮转 |
| 关闭顺序 | 停止输入 -> 零命令 -> 注销 subscriber -> 停 worker -> 释放 OpenGL -> 结束 eCAL |
| 单点故障 | Viewer/RViz/3D 面板故障不终止物理仿真；Command/Simulator 故障触发全局停车 |

不得用降低射线数、传感器频率或物理步频掩盖性能问题。render drop 与 protocol drop 分开统计；前者允许在 GUI 负载高时增长，后者在正常验收负载下应为零。

## 7. 实施顺序

1. 完成 eCAL 环境注入、预检和五 topic 真实收发，先恢复 Dashboard 数据源。
2. 接入 Dashboard eCAL snapshot 与折线图，建立 session、descriptor、sequence 和超时门禁。
3. 以独立 worker 和容量 1 队列实现内嵌 3D 点云，再加入带位姿的时间窗累积和诊断终端。
4. 修复采集命名、原子导出和 Viewer 状态机。
5. 从参考文件提取串口 parser，完成设备扫描、Command 仲裁和失联停车。
6. 运行 GUI、真实 eCAL、串口和 Viewer 联合验收；修复后再构建最终 `.run`。

每个 P0 行为按聚焦测试 RED、最小实现 GREEN、直接相关回归的顺序完成。跨进程和 GUI 条目增加真实运行证据，mock 测试不能替代最终门禁。
